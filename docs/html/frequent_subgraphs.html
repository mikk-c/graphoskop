Frequent subgraph mining

Frequent subgraph mining: the labeled subgraphs (patterns) that occur in many graphs of a database.

In transactional mining (transactional_graph_mining()) the database is a network and each of its connected components is a graph (a transaction); the support of a pattern is the number of components that contain it (as a subgraph, not necessarily induced), and a pattern is frequent if its support reaches a threshold. In single graph mining (single_graph_mining()) the network is analyzed as a whole, and the support of a pattern is its minimum image based support (MNI): the least number of distinct network nodes onto which one of its nodes is mapped. Nodes and edges may carry labels, taken from a node attribute and an edge attribute (or the layer, in multilayer networks), and patterns must match them.

The search is gSpan (Yan and Han, 2002). A pattern is written as a DFS code, the list of its edges in the order of a depth first visit, each with the labels of its endpoints; among the codes of a pattern, the lexicographically smallest one, the minimum DFS code, is its canonical form. Patterns grow one edge at a time, only from the end of their code (rightmost extensions: a new node attached to the rightmost path of the visit, or an edge back from its last node), so that every pattern has a single parent, the pattern of its code minus the last edge, and the search space is a tree:

  • the search starts from single labeled nodes and single edges; node labels and edge types (node label, edge label, node label) that are not frequent are removed from the database first, so no pattern containing them is ever built;

  • in transactional mining, every pattern keeps the list of its embeddings (where it occurs, node by node) in the database; its extensions and their supports are all counted in one vectorized pass over these embeddings, without any subgraph isomorphism test (single graph mining keeps the valid images of each pattern node instead, see single_graph_mining());

  • an extension that is not frequent is dropped there and never extended: support is anti-monotone, so none of its super-patterns can be frequent. A super-pattern reached from another, frequent parent is counted in that parent’s pass and dropped in the same way;

  • an extension whose code is not the minimum DFS code of its pattern is a duplicate of a pattern found (or to be found) through its canonical parent, and is dropped with its whole subtree.

A frequent pattern is maximal if no frequent pattern contains it: if no extension by one edge, anywhere in the pattern, is frequent. Frequent patterns that differ by one edge give association rules (graph_association_rules()), which can score node pairs for link prediction (association_rules_lp()).

import graphoskop as gsk

db = gsk.load_network("molecules.tsv", "atoms.tsv")         # one molecule per component
patterns, support = gsk.transactional_graph_mining(db, 100, node_label = "element", edge_label = "bond")
support.sort_values("support", ascending = False).head()   # most frequent patterns
list(patterns.edges(3, labels = True, data = "bond"))       # edges of pattern 3
top, support = gsk.transactional_graph_mining(db, 0.1, node_label = "element", maximal = True)

ml = gsk.load_network("layers.tsv", multilayer = True)      # layers as edge labels
patterns, support = gsk.transactional_graph_mining(ml, 5, edge_label = gsk.LAYER, max_edges = 4)

net = gsk.load_network("citations.tsv", "papers.tsv", directed = True)   # a single network
patterns, support = gsk.single_graph_mining(net, 500, node_label = "field", max_edges = 4)

rules = gsk.graph_association_rules(net, patterns, support, transactional = False)
rules[rules["confidence"] > 0.5].sort_values("lift", ascending = False)
graphoskop.graph_association_rules(net, patterns, support, transactional=True)

Association rules between frequent patterns that differ by one edge: the smaller pattern P (the antecedent) and the larger one Q (the consequent), Q being P with one more edge (between two of its nodes, or to a new node).

Since Q contains P, the support of the rule is the support of Q, and its confidence \(\sup(Q) / \sup(P)\) the share of the support of P that extends to Q (at most 1, support being anti-monotone). The lift compares this confidence with the relative support of the added edge alone, E, the one-edge pattern with the labels (and direction) of the new edge and its endpoints: \(\text{lift} = \text{confidence} / (\sup(E) / N)\), above 1 when P makes the new edge more likely than in general (when P is a single node, Q is E itself and the lift reduces to \(N / \sup(P)\)). N is the number of graphs of the database (components; components of the network of entities for a multilayer network mined with the layer as edge label) with transactional = True, or the number of nodes (entities) for MNI, with transactional = False.

Patterns are matched by their minimum DFS codes, with the labels stored in patterns. All the frequent patterns are needed: with the maximal ones only (maximal = True) almost no pair is left. If two different edges of Q give the same P with different edge labels, the rule uses the first one for the lift.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – The network that was mined.

  • patterns – Pattern network returned by transactional_graph_mining() or single_graph_mining().

  • support – Support table returned with patterns.

  • transactional – Whether the patterns come from transactional_graph_mining() (or from single_graph_mining()).

Returns:

pandas.DataFrame with columns antecedent and consequent (pattern ids, the components of patterns), support, confidence and lift, one row per pair.

Example:

import graphoskop as gsk

db = gsk.load_network("molecules.tsv", "atoms.tsv")
patterns, support = gsk.transactional_graph_mining(db, 100, node_label = "element")
rules = gsk.graph_association_rules(db, patterns, support)
rules[rules["confidence"] > 0.9].sort_values("lift", ascending = False)
graphoskop.single_graph_mining(net, min_support, node_label=None, edge_label=None, maximal=False, max_edges=None)

Frequent subgraphs of a single network: the connected labeled patterns whose minimum image based support (MNI; Bringmann and Nijssen, 2008) reaches min_support.

The network is mined as a whole. Counting the occurrences of a pattern is not anti-monotone (a star with three leaves occurs more often than the edge it contains, around a hub), so the support of a pattern is instead, over its nodes, the least number of distinct network nodes onto which the node is mapped by some embedding (an occurrence as a subgraph, not necessarily induced, with the same labels and directions). MNI never grows when a pattern grows, so the search can stop at infrequent patterns; it is never larger than the number of occurrences up to automorphisms, and is close to it when occurrences overlap little.

Patterns grow as in transactional_graph_mining() (gSpan’s minimum DFS codes and rightmost extensions, single labeled nodes first), with the same labels, multilayer collapse, options and output. Instead of storing every embedding, which explodes around hubs in a large network, every pattern keeps the set of valid images of each of its nodes, as in GraMi (Elseidy et al., 2014): an extension can map these nodes only onto them (its candidates), is skipped if its new edge leaves or reaches fewer distinct valid images than the threshold, has its candidates filtered by arc consistency, and then, for each node, each remaining candidate is checked by searching an embedding that maps the node onto it (a compiled search, candidates in parallel): every embedding found validates all its nodes at once, and the check stops as soon as the threshold is out of reach.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • min_support – Least MNI of a pattern, a positive integer.

  • node_label – Name of the node attribute giving the node labels, or None.

  • edge_label – Name of the edge attribute giving the edge labels, LAYER in multilayer networks, or None.

  • maximal – Whether to report only maximal patterns: those contained in no other frequent pattern (whatever max_edges).

  • max_edges – Largest number of edges of a pattern (None: no limit).

Returns:

(patterns, support), as transactional_graph_mining(), with support the MNI of each pattern.

Raises:

ValueError – If min_support is not a positive integer, or if an entity has different node labels in different layers.

Example:

import graphoskop as gsk

net = gsk.load_network("citations.tsv", "papers.tsv", directed = True)
patterns, support = gsk.single_graph_mining(net, 500, node_label = "field", max_edges = 4)
support.sort_values("support", ascending = False).head()
graphoskop.transactional_graph_mining(net, min_support, node_label=None, edge_label=None, maximal=False, max_edges=None)

Frequent subgraphs of a database of graphs, the connected components of a network: the connected labeled patterns that occur in at least min_support components, found with gSpan (see the module description).

A pattern occurs in a component if some of its nodes and edges form a copy of the pattern (a subgraph, not necessarily induced), with the same node labels (the values of the node attribute node_label), the same edge labels (the values of the edge attribute edge_label) and, in directed networks, the same edge directions. Both attributes can be numeric or qualitative. Without node_label (edge_label), all nodes (edges) have the same label; NaN is a label like any other. Patterns start from single labeled nodes and grow one edge at a time; every frequent pattern is reported once, with its support.

In a multilayer network, edge_label = LAYER makes the layer the edge label: couplings and other interlayer edges are ignored, the copies of each entity collapse into one node, and an edge present in several layers becomes parallel edges with different labels (a labeled multigraph); the graphs of the database are then the connected components of this network of entities. node_label must then have the same value in all the copies of an entity. With another edge label, a multilayer network is mined as its supra-graph.

Self loops are ignored, and parallel edges with the same label count as one edge. The number of frequent patterns can grow exponentially as min_support decreases; max_edges bounds the size of the patterns.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • min_support – Least number of components containing a pattern; a number between 0 and 1 (excluded) is a fraction of the number of components.

  • node_label – Name of the node attribute giving the node labels, or None.

  • edge_label – Name of the edge attribute giving the edge labels, LAYER in multilayer networks, or None.

  • maximal – Whether to report only maximal patterns: those contained in no other frequent pattern (whatever max_edges).

  • max_edges – Largest number of edges of a pattern (None: no limit).

Returns:

(patterns, support): a Network with one component per pattern, directed if net is, with node ids 0, 1, ... in component order and only the labels as attributes (node attribute node_label, edge attribute edge_label; with LAYER, the position of the layer in net.layer_labels); and a pandas.DataFrame with columns pattern (index of the component of patterns) and support (number of components of net containing it). patterns is None if no pattern is frequent.

Raises:

ValueError – If min_support is not positive, or if an entity has different node labels in different layers.

Example:

import graphoskop as gsk

db = gsk.load_network("molecules.tsv", "atoms.tsv")        # one molecule per component
patterns, support = gsk.transactional_graph_mining(db, 100, node_label = "element", edge_label = "bond")
support.sort_values("support", ascending = False).head()
patterns.number_of_nodes(3)                              # size of pattern 3
big, support = gsk.transactional_graph_mining(db, 0.1, node_label = "element", maximal = True)

Performance

On two CPU threads, with databases of random molecule-like graphs (15 to 30 nodes, a tree plus one to three rings, four node labels and two edge labels): 300 graphs, support 20%, 251 frequent patterns in 0.7 s (0.9 s for the 112 maximal ones); support 10%, 910 patterns in 1.5 s; 1000 graphs, support 10%, 831 patterns in 3.8 s (maximal: 5.3 s). The pure Python gSpan of the gspan-mining package finds the same patterns (it does not report single nodes) in 3.9 s, 7.8 s and 22 s.

In a single network (single_graph_mining()), with Barabási-Albert networks whose nodes have one of three random labels: 10,000 nodes and 30,000 edges, MNI threshold 500, 169 frequent patterns (up to 5 edges) in 2.1 s, the 94 maximal ones in 4.6 s; 100,000 nodes and 300,000 edges, threshold 5,000, 75 patterns up to 3 edges in 3.6 s and 156 up to 4 edges in 10.5 s.

graph_association_rules() matches patterns by their canonical codes: the 2,088 rules between the 831 patterns of the 1,000 molecule-like graphs take 0.25 s.
