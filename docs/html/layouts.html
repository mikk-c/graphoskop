Layouts

Network layouts: positions of the nodes in the plane or in space, to draw a network.

Layout functions store the positions as numeric node attributes pos_x, pos_y and, in three dimensions, pos_z (the prefix pos can be changed), so that any plotting library can draw the network from get_node_attribute() or from the node table of to_pandas_dataframes(). They also return the positions as a pandas.DataFrame.

Six families of layouts are available: circular, grid and matrix layouts, driven by node attributes (groups and orders) and by the edges between groups; force-directed layouts, driven by the edges; hierarchical layouts, in layers given by the direction of the edges, by a node attribute or by the distance from a root; and UMAP layouts, driven by node vectors (node attributes, embeddings, or the adjacency matrix). Any layout can then be mirrored, rotated and zoomed, and its overlaps removed, and its edges can be bundled.

Circular layouts

Circular layouts put the nodes of every component on a circle. Hierarchical groups become sectors of sectors, arranged so that groups sharing many edges are close, and a numeric attribute, or the edges to the neighboring sectors, orders the nodes inside each sector.

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
gsk.circular_layout(net, ["region", "city"], order = "age")
gsk.circular_layout(net, "community")      # inside sectors: by edges to the adjacent sectors
graphoskop.circular_layout(net, groups=None, order=None, weight=None, spacing=1.0, gap=1.0, attribute='pos', arrange=True)

Circular layout: the nodes of every component on a circle, in sectors by group (hierarchical groups nest, as sectors of sectors), and in each sector in the order given by a numeric attribute or by their edges.

  • groups: one node attribute or a list of them, by decreasing importance: nodes with the same value of the first share a sector of the circle; inside it, nodes with the same value of the second share a smaller sector; and so on. Attributes can be qualitative or numeric: their distinct values are the groups (numeric codes of communities work as groups; nodes with missing values form one more group). Empty slots (gap times the number of levels below the one that changes) separate the sectors: wider gaps between the sectors of the first attribute, narrower between finer ones.

  • Sectors are arranged by their edges (arrange = True), level by level from the first: inside the sector of their parent group (around the whole circle for the first attribute), groups with many edges between them are placed close, and groups with many edges to the previous (next) sector of the parent’s level near its start (end). The arrangement minimizes the sum, over pairs of groups, of their edges (or weights) times the distance between the centers of their arcs, plus the edges to the adjacent sectors times the distance from them: exactly for up to 7 groups in a sector; above, from the order of the Fiedler vector (the angle in the spectral embedding, around the whole circle), improved by moving one group at a time where it lowers the sum most, up to 50 groups (by swapping neighboring groups up to 200; spectral order only above). Groups without edges keep the order of their values. With arrange = False, sectors follow the sorted order of the values (numbers numerically, text alphabetically), clockwise from the top, missing values last; useful for ordered groups (age classes, years).

  • order: a numeric node attribute sorting the nodes inside the finest sectors (or around the whole circle without groups), clockwise by increasing value; missing values last.

  • Without order, nodes inside a sector are sorted by their edges to the two adjacent sectors of the same level of detail: if sectors a, b, c follow each other, the nodes of b go from those with edges mostly to a (next to a) to those with edges mostly to c (next to c), by \((e_c - e_a) / (e_c + e_a)\); nodes with neither stay in the middle, in the network order. This takes one pass over the edges (components with fewer than 3 sectors have no distinct neighbors on both sides, so their nodes keep the network order).

  • Without groups and order, nodes are sorted by their angle in the Laplacian eigenmap of their component (laplacian_eigenmaps(), 2 dimensions): neighbors end up close on the circle, which makes fewer and shorter chords than a random order.

Each sector gets an arc proportional to its number of nodes. Every component has its own circle, with consecutive nodes spacing apart along it (its radius grows with the number of nodes); the circles are packed in rows, largest component first (as in force_directed_layout()). Directed networks are treated as undirected.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • groups – Name of a node attribute, or list of names in order of importance, or None.

  • order – Name of a numeric node attribute sorting the nodes in their sectors, or None.

  • weight – Name of a numeric edge attribute: without order, nodes are sorted by the weights of their edges to the adjacent sectors instead of their number (and the Laplacian eigenmap, without groups, is weighted); None counts edges.

  • spacing – Distance between consecutive nodes along a circle.

  • gap – Empty slots between sectors, per level of groups below the level that changes; 0 for none.

  • attribute – Prefix of the numeric node attributes <attribute>_x, <attribute>_y where to store the positions, or None to only return them.

  • arrange – Whether to arrange the sectors by their edges (True) or in sorted order of the group values (False).

Returns:

pandas.DataFrame with one row per node, indexed by node id, in the network wide node order, and the columns <attribute>_x, <attribute>_y (x, y with attribute = None).

Raises:

  • KeyError – If an attribute does not exist.

  • ValueError – If order is not a numeric node attribute.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
gsk.circular_layout(net)                                  # neighbors close on the circle
gsk.circular_layout(net, order = "age")                   # clockwise by age
gsk.circular_layout(net, ["country", "city"])             # sectors of sectors
gsk.circular_layout(net, ["country", "city"], order = "age")
gsk.circular_layout(net, "age_class", arrange = False)    # sectors in order of the values

Edge bundling

Edge bundling draws the edges as curves that follow a hierarchy of groups of the nodes (hierarchical edge bundling, as in graph-tool): edges between the same groups run together, and the drawing shows how groups connect rather than a tangle of lines. The hierarchy can be given by node attributes (from the coarsest level), such as the levels of a nested blockmodel, or found in the layout itself. The curves are returned as chains of cubic Bézier curves (as graph-tool does), which plotting libraries draw exactly.

import graphoskop as gsk

net = gsk.load_network("edges.tsv")
gsk.block_model_communities(net)                        # community, community_1, ...
levels = ["community_2", "community_1", "community"]
gsk.circular_layout(net, groups = levels)
bends = gsk.bundle_edges(net, groups = levels)          # graph-tool's look
gsk.force_directed_layout(net)
bends = gsk.bundle_edges(net, beta = 0.6)               # hierarchy of the layout's space
graphoskop.bundle_edges(net, groups=None, beta=0.8, attribute='pos')

Hierarchical edge bundling (Holten, 2006), as in graph-tool: every edge is drawn as a curve that follows the hierarchy of groups of the nodes, so that edges between the same groups run together in bundles and the drawing shows the connections between groups rather than a tangle of lines.

The hierarchy is a tree: its leaves are the nodes, above them the groups of the finest level, then the groups that contain them, up to one root per component. Every group sits at the center (mean position) of its nodes in the current layout. The curve of an edge between \(u\) and \(v\) is a cubic B-spline whose control points are the path in the tree from \(u\) up to the smallest group containing both, and down to \(v\). As in graph-tool, the curve is returned as cubic Bézier curves, which drawing libraries draw exactly at any zoom. The strength beta straightens the path: every control point \(p_i\) of a path of \(k\) points moves to \(\beta p_i + (1 - \beta) (p_0 + \frac{i}{k - 1} (p_{k - 1} - p_0))\), so that beta = 0 gives straight edges and beta = 1 curves that follow the hierarchy closely; the default 0.8 is graph-tool’s. Edges within a finest group bend through its center only.

  • groups: node attributes from the coarsest to the finest level, as the groups of circular_layout() (distinct values are groups, missing values one more group; a group of a level is split by the values of the next one). For the look of graph-tool’s nested blockmodel drawings, fit the hierarchy with block_model_communities(), which writes the levels community (finest), community_1, …, and use them both for circular_layout() and here (see the example).

  • Without groups, the hierarchy comes from the layout itself: clusters of the positions (k-means), 8 at the first level, 64 at the second, and so on, each split by the clusters of the next level, until groups have about 4 nodes. Edges then bundle between regions of the drawing, for any layout.

The curve of every edge is a chain of cubic Bézier curves: points 0, 3, 6, … are on the curve, the two points between each pair of them are the control points of that piece (piece \(i\) is the Bézier curve of points \(3i\) to \(3i + 3\)). Edges have more pieces the further apart their nodes are in the hierarchy (one for edges within a finest group). Edges are taken as given in input, in the order of edges() over all components (component = None); a self loop stays on its node. Computing the curves takes one pass over the edges per level of the hierarchy. The positions are not changed: run the function again after another layout.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network with positions in the node attributes <attribute>_x, <attribute>_y (and <attribute>_z).

  • groups – Name of a node attribute, or list of names from the coarsest level to the finest, or None for a hierarchy of the space of the layout.

  • beta – Strength of the bundling, from 0 (straight edges) to 1.

  • attribute – Prefix of the position attributes.

Returns:

pandas.DataFrame with one row per Bézier point, edge by edge: the position of the edge (edge), the position of the point along its curve (point, 0 at the source) and its coordinates x, y (and z).

Raises:

  • KeyError – If the network has no positions with that prefix, or an attribute does not exist.

  • ValueError – If beta is not between 0 and 1.

Example:

import graphoskop as gsk
import matplotlib.pyplot as plt
from matplotlib.patches import PathPatch
from matplotlib.path import Path

net = gsk.load_network("edges.tsv")
gsk.block_model_communities(net)                          # community, community_1, ...
levels = ["community_2", "community_1", "community"]      # coarsest first
gsk.circular_layout(net, groups = levels)
bends = gsk.bundle_edges(net, groups = levels)
ax = plt.gca()
for e, curve in bends.groupby("edge"):
   xy = curve[["x", "y"]].to_numpy()
   path = Path(xy, [Path.MOVETO] + [Path.CURVE4] * (len(xy) - 1))
   ax.add_patch(PathPatch(path, fill = False, edgecolor = "gray", alpha = 0.3, lw = 0.5))

Force-directed layouts

Force-directed layouts treat edges as springs pulling their nodes together and nodes as particles pushing each other apart, and let the nodes move until the forces balance. The layout of graphoskop aims at the look of organic layouts: groups of nodes that share many edges stay together, the drawing takes the shape of the network rather than of a disk, and nodes with few edges stay next to their neighbors instead of being thrown to the border.

import graphoskop as gsk
import matplotlib.pyplot as plt
from matplotlib.collections import LineCollection

net = gsk.planted_partition_graph([40] * 6, 0.25, 0.005, seed = 1)
pos = gsk.force_directed_layout(net, seed = 0)          # node attributes pos_x, pos_y
xy = {node: p for node, p in zip(pos.index, pos.values)}
edges = [(xy[a], xy[b]) for a, b in net.edges(None, labels = True)]
community = net.to_pandas_dataframes()[1].set_index("node").loc[pos.index, "community"]
fig, ax = plt.subplots()
ax.add_collection(LineCollection(edges, colors = "gray", linewidths = 0.4, zorder = 1))
ax.scatter(pos.pos_x, pos.pos_y, s = 8, c = community, cmap = "tab10", zorder = 2)
ax.set_aspect("equal")
ax.axis("off")

clustering trades uniform edge lengths (0) for groups further apart (1), joined by longer edges; the default, 0.25, leans towards uniform edges. Positions in three dimensions are stored in pos_x, pos_y and pos_z.

graphoskop.force_directed_layout(net, dimensions=2, weight=None, iterations=200, clustering=0.25, edge_length=1.0, seed=None, attribute='pos', progress=None)

Force-directed layout in the spirit of organic layouts (such as yFiles’ Organic layout): edges pull their nodes together, all nodes push each other apart, and the nodes move until the forces balance. Groups of nodes sharing many edges end up together, apart from the rest of the network; the shape of the drawing follows the network, not a circle or a sphere; nodes with one or few edges stay close to their neighbors.

The layout minimizes the energy of the edge-repulsion model of Noack (2007),

\[U = \sum_{(u, v) \in E} w_{uv} \frac{d_{uv}^a}{a} + C \sum_{u < v} \frac{(k_u + 1)(k_v + 1)}{d_{uv}}, \qquad a = 2 - \mathrm{clustering},\]

where \(d_{uv}\) is the distance between two nodes, \(w_{uv}\) the weight of their edge (1 without weight) and \(k_u\) the number of neighbors of \(u\). Three choices set its look apart from classical spring embedders (Fruchterman and Reingold):

  • Repulsion is weighted by degree (plus one), so every node is pushed away in proportion to the edges pulling it back: a leaf is not shot away from its only neighbor by the whole network, and hubs, with all their neighbors, keep their distances.

  • The repulsion force decays as \(1 / d^2\), faster than \(1 / d\), and there is no gravity towards the center and no frame: far away parts of the network do not press the drawing into a disk, its shape comes from the edges.

  • The attraction exponent \(a\) sets how strongly groups separate: with \(a = 2\) (clustering = 0, springs as in ForceAtlas2) edges have similar lengths and groups touch; with \(a = 1\) (clustering = 1, the LinLog attraction of Noack) densely connected groups shrink and move apart, joined by long edges, which shows communities best but makes trees spiky. Long edges are the edges between groups, stretched by design: on a network of 24,880 nodes with 22 communities, 84% of the edges longer than 5 times the median joined two communities. The default, 0.25, came from that network: compared with 0.5, it halves those long edges (from 3.4% to 1.9% of all edges) while the 10 nearest nodes of a node are still 71% in its community (75% with 0.5, 67% with 0). Neither the degree weighting of the repulsion nor weighting edges by their common neighbors gave a better balance, and the layout does not depend on the seed or on a hotter start.

Each component is laid out on its own. It starts from pivot multidimensional scaling (Brandes and Pich, 2006: classical scaling of the hop distances from 50 random pivots), which already places nodes as their distances in the network say, then takes iterations steps along the forces divided by degree plus one, each capped by a temperature cooling from 1 to 0.01 mean edge lengths. \(C\) makes the starting scale a stationary point of the energy. After each step, nodes with at most 3 neighbors closer than 0.7 mean edge lengths to another such node of their component are pushed apart, so that leaves around a hub do not pile up. Repulsion is exact, over all pairs, in components of at most 256 nodes (laid out together, in batches); in larger ones it is approximated on nested grids, Barnes-Hut style: nodes in the same or adjacent cells of the finest grid repel exactly, farther ones as the total degree of their cell at its center of mass (errors about 0.1% of the mean force on test layouts), in time linear in the number of nodes. Everything runs on the device of the network.

Finally every component is rotated onto its principal axes (its widest extent along pos_x), scaled to a mean edge length of edge_length, and the components are packed in rows, largest first, two edge lengths apart; isolated nodes come last. Directed networks are laid out as undirected, self loops are ignored, parallel and reciprocal edges merged (weights summed). In multilayer networks every copy of a node is a node of its own, held near its other copies by the interlayer edges.

Runtime, with the default 200 iterations on two CPU threads: about 2.5 s for 1,000 nodes, 20 s for 10,000 and 110 s for 50,000 (LFR benchmark graphs, average degree 15). Time grows about linearly with nodes, edges and iterations; large networks are best laid out on a GPU.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • dimensions – 2 (pos_x, pos_y) or 3 (also pos_z).

  • weight – Name of a numeric edge attribute: edges with larger weights pull harder (weights are rescaled to mean 1), or None.

  • iterations – Number of steps after the initial layout.

  • clustering – Between 0 and 1: how strongly densely connected groups are kept together and apart from the rest (see above).

  • edge_length – Mean length of the edges in the result.

  • seed – Seed of the random pivots and of the small initial perturbation, for reproducible layouts.

  • attribute – Prefix of the numeric node attributes <attribute>_x, <attribute>_y (and <attribute>_z) where to store the positions, or None to only return them.

  • progress – Whether to show a progress bar (see Progress bars); None uses the global setting.

Returns:

pandas.DataFrame with one row per node, indexed by node id, in the network wide node order, and one column per dimension (named as the attributes, or x, y, z).

Raises:

ValueError – If dimensions is not 2 or 3, clustering is not between 0 and 1, iterations is negative, or weights are negative or missing.

Example:

import graphoskop as gsk
import matplotlib.pyplot as plt

net = gsk.load_network("edges.tsv")
pos = gsk.force_directed_layout(net, seed = 0)    # also node attributes pos_x, pos_y
edges = [(pos.loc[a], pos.loc[b]) for a, b in net.edges(None, labels = True)]
for a, b in edges:
   plt.plot([a.pos_x, b.pos_x], [a.pos_y, b.pos_y], color = "gray", lw = 0.5, zorder = 1)
plt.scatter(pos.pos_x, pos.pos_y, s = 10, zorder = 2)
plt.gca().set_aspect("equal")

gsk.force_directed_layout(net, clustering = 1)    # communities further apart
gsk.force_directed_layout(net, 3, attribute = "pos3d")   # pos3d_x, pos3d_y, pos3d_z

Grid layouts

Grid layouts put the nodes on the cells of a regular grid. They work as circular layouts do, in two dimensions: hierarchical groups become blocks of blocks, groups sharing many edges are side by side, and inside each block nodes linked to other blocks sit on the border facing them, the others in the middle (or a numeric attribute fills the block in reading order).

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
gsk.grid_layout(net, ["region", "city"])
gsk.grid_layout(net, "community", order = "age")
graphoskop.grid_layout(net, groups=None, order=None, weight=None, spacing=1.0, gap=1.0, attribute='pos', arrange=True)

Grid layout: the nodes of every component on the cells of a regular grid, in rectangular blocks by group (hierarchical groups nest, as blocks of blocks), the counterpart of circular_layout() on a grid.

  • groups: one node attribute or a list of them, by decreasing importance; their distinct values are the groups (qualitative or numeric). Every group of the last attribute is a block of about square shape (ceil(sqrt(n)) columns); the blocks of a group of the attribute above are packed in rows of about the width of a square holding them, the rows snaking left to right and right to left so that consecutive blocks stay side by side; and so on up to the whole component. Empty cells (gap times the number of levels below the one that changes) separate the blocks: wider gaps between the blocks of the first attribute.

  • The order of the blocks follows the arrangement of circular_layout() (arrange = True): groups with many edges between them are consecutive, and so side by side, and groups with many edges to the previous (next) block of their parent’s level come first (last), along the line of the snaking rows instead of around a circle. With arrange = False, blocks follow the sorted order of the values.

  • order: a numeric node attribute filling every block row by row (reading order) by increasing value, missing values last.

  • Without order, nodes are placed in their block by their edges to other blocks: each node is pulled from the center of its block towards the centers of the blocks of its neighbors in other groups (weighted by the edges), as far as the rank of its number of such edges in its block, then nodes are snapped to the cells (sorted into columns by their target column, then within columns by their target row). Nodes without edges to other groups fill the middle of the block, those with many fill its borders, on the side of the blocks they are linked to.

  • Without groups and order, every component is one block and nodes are snapped from their position in the Laplacian eigenmap of the component (laplacian_eigenmaps(), 2 dimensions), so that neighbors are close; the embedding is turned (in steps of 5 degrees) to the angle giving the shortest edges on the grid (a lattice network comes back as a lattice).

Columns and rows are spacing apart; rows go downwards. Components get their own grids, packed in rows, largest first (as in force_directed_layout()). Directed networks are treated as undirected.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • groups – Name of a node attribute, or list of names in order of importance, or None.

  • order – Name of a numeric node attribute sorting the nodes in their blocks, or None.

  • weight – Name of a numeric edge attribute weighting the edges in the arrangement of the blocks and the placement of the nodes, or None.

  • spacing – Distance between consecutive columns and rows.

  • gap – Empty cells between blocks, per level of groups below the level that changes; 0 for none.

  • attribute – Prefix of the numeric node attributes <attribute>_x, <attribute>_y where to store the positions, or None to only return them.

  • arrange – Whether to arrange the blocks by their edges (True) or in sorted order of the group values (False).

Returns:

pandas.DataFrame with one row per node, indexed by node id, in the network wide node order, and the columns <attribute>_x, <attribute>_y (x, y with attribute = None).

Raises:

  • KeyError – If an attribute does not exist.

  • ValueError – If order is not a numeric node attribute.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
gsk.grid_layout(net)                                  # neighbors close on the grid
gsk.grid_layout(net, ["country", "city"])             # blocks of blocks
gsk.grid_layout(net, "community", order = "age")      # blocks filled by age

Hierarchical layouts

Hierarchical (layered) layouts draw directed acyclic networks with all edges pointing down, trees from their root, and any network in layers given by a node attribute, with few edge crossings and parents above the middle of their children. Radial layouts put the layers on concentric circles instead, the root at the center, each subtree in its own wedge.

import graphoskop as gsk

net = gsk.load_network("citations.tsv", directed = True)
gsk.hierarchical_layout(net)                                   # edges point down
gsk.hierarchical_layout(net, levels = "year", direction = "right")
tree = gsk.load_network("tree.tsv")
gsk.hierarchical_layout(tree, root = "ceo", direction = "radial")   # inside out
graphoskop.hierarchical_layout(net, levels=None, root=None, direction='down', spacing=1.0, layer_spacing=2.0, attribute='pos')

Hierarchical (layered) layout, in the style of Sugiyama, Tagawa and Toda (1981): nodes in horizontal layers, edges going from one layer to the next, few edge crossings, and every node near the middle of its neighbors.

  1. Layers. With levels, the distinct values of a numeric node attribute, in increasing order (for instance a year, or a rank from agony_hierarchy()); missing values make the last layer. Otherwise, in directed networks, every node goes one layer below its lowest predecessor (longest path from the sources), so that all edges point down; in networks with cycles, the edges that close a cycle in a depth-first search from the sources point up instead (as in Graphviz’s dot). In undirected networks, the layer is the distance from a root: the node given in root for its component, or the node with most neighbors (trees drawn from their hub).

  2. Order in the layers, to reduce crossings: layer after layer, alternately downwards and upwards, the nodes of a layer are sorted by the mean position of their neighbors in the layers above (below) (barycenter heuristic, 25 passes, the last downwards). Edges spanning several layers count with the position of their other end, edges inside a layer are not used.

  3. Positions in the layers: every node is pulled to the mean position of its neighbors in the layers below (nodes without any, such as leaves, to those above), keeping the order and at least spacing between consecutive nodes (an isotonic regression per layer, 30 rounds), so that parents sit above the middle of their children, as in tidy tree drawings.

  4. With direction = "radial", layers become concentric circles, from the inside out, as the radial tree drawings of Eades (1992): in a spanning tree (the parent of a node is its neighbor in the closest layer above, the nearest in position), every node gets a wedge of the circle proportional to the number of leaves below it, its children splitting the wedge in their order in the layers (clockwise from the top), and sits in the middle of its wedge; so every leaf has its own angle, whatever its depth, and parents sit at the middle angle of their children. Children fan out at most 45 degrees from their parent (their wedges shrinking around it if needed), since edges spanning wider angles would bend back inside the circle of the parent and cross other edges. A first layer of one node (a root) is at the center; every circle is layer_spacing beyond the previous one, or farther where consecutive nodes on it would otherwise be closer than spacing (inner circles then grow in proportion, so that radii rise evenly). Radial layouts suit trees and hierarchies; edges outside the spanning tree, as in networks with many paths between layers, become chords.

Each component is laid out on its own and the components are packed in rows, largest first (as in force_directed_layout()).

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • levels – Name of a numeric node attribute giving the layers, or None.

  • root – Without levels, in undirected networks: the node id (or a list of ids, one per component) at the top; None for the node with most neighbors of each component.

  • direction – Where the layers go: "down" (first layer at the top), "up", "right", "left", or "radial" (first layer at the center, the others on concentric circles around it).

  • spacing – Smallest distance between nodes of a layer.

  • layer_spacing – Distance between consecutive layers.

  • attribute – Prefix of the numeric node attributes <attribute>_x, <attribute>_y where to store the positions, or None to only return them.

Returns:

pandas.DataFrame with one row per node, indexed by node id, in the network wide node order, and the columns <attribute>_x, <attribute>_y (x, y with attribute = None).

Raises:

  • KeyError – If levels or a root does not exist.

  • ValueError – If direction is unknown.

Example:

import graphoskop as gsk

net = gsk.load_network("citations.tsv", directed = True)
gsk.hierarchical_layout(net)                        # edges point down
gsk.hierarchical_layout(net, levels = "year", direction = "right")
tree = gsk.load_network("tree.tsv")
gsk.hierarchical_layout(tree, root = "ceo")
gsk.hierarchical_layout(tree, root = "ceo", direction = "radial")   # root at the center

Matrix layouts

Matrix layouts order the rows and columns of the adjacency matrix, to draw it as a matrix (heat map): one order for square matrices, independent orders for the rows and columns of bipartite networks. Groups become blocks, and the network’s structure places similar rows and columns next to each other; sorting by degree draws nested networks as triangles.

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
gsk.matrix_layout(net, "community")                  # communities as blocks on the diagonal
bip = gsk.load_network("plants_pollinators.tsv", "species.tsv", bipartite = True)

graphoskop.matrix_layout(net, groups=None, order=None, column_groups=None, column_order=None, weight=None, descending=False, gap=0.0, attribute='matrix', arrange=True)

Order of the rows and columns of the adjacency matrix, to draw it (a matrix, or heat map, visualization): the counterpart of circular_layout() along a line, with the network’s own structure, groups and numeric attributes placing similar rows and columns next to each other.

Square matrices (one-mode networks): rows and columns follow the same order. With groups (one node attribute or a list, by decreasing importance), the nodes of every group are consecutive, inside the range of their parent group, and groups are arranged as the sectors of circular_layout(), along a line instead of a circle: groups with many edges between them are close (the sum of their edges times their distance is minimized), and groups with many edges to the previous (next) group of the level above come first (last); with arrange = False, groups follow the sorted order of their values. Inside the finest groups, nodes are sorted by order, or else by their edges to the previous and next group, from those with edges mostly to the previous one to those with edges mostly to the next one. Without groups and order, nodes are sorted by the Fiedler vector of their component (the second eigenvector of the normalized Laplacian: spectral seriation), which puts densely connected nodes next to each other: communities become blocks on the diagonal, clearly when there are few of them (with many, give them as groups, from any community detection).

Rectangular matrices (bipartite networks): rows are the nodes of the first type, columns those of the second, and each axis has its own groups and order (groups and order for the rows, column_groups and column_order for the columns, each a mix of qualitative and numeric attributes as above). Rows have no edges between them, so they are placed by the columns they are linked to, and columns by their rows: starting from the spectral co-clustering order (the Fiedler vector of the bipartite network, Dhillon 2001), each row moves to the mean position of its columns and each column to the mean position of its rows, alternately, 20 times (the barycenter method of two-layer drawings), groups moving as wholes (by the mean of their members, inside their parent group; with arrange = False in the order of their values) and nodes with an order sorted by it inside their finest group. Dense blocks gather near the diagonal.

order = "degree" sorts by the sums of the rows (columns), the weighted degree with weight (in directed networks, in and out edges together); with descending = True, the fullest rows come first, so matrix_layout(net, order = "degree", column_order = "degree", descending = True) draws a nested bipartite network as an upper triangular matrix (see nestedness()).

Components follow each other along the diagonal, largest first. The positions are stored as one numeric node attribute: the row of a node, which in square matrices is also its column; in bipartite networks the row of a node of the first type and the column of a node of the second.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • groups – Name of a node attribute, or list of names in order of importance, grouping the rows (and columns of square matrices), or None.

  • order – "degree", or the name of a numeric node attribute, sorting the rows (and columns of square matrices) inside their finest groups, or None.

  • column_groups – As groups, for the columns of a bipartite network.

  • column_order – As order, for the columns of a bipartite network.

  • weight – Name of a numeric edge attribute weighting the edges (in the arrangements, the barycenters and "degree"), or None.

  • descending – Whether orders go from the largest value to the smallest.

  • gap – Empty rows (columns) between groups, per level of groups below the level that changes (components count as one more level); 0 for none.

  • attribute – Name of the numeric node attribute where to store the positions, or None to only return them.

  • arrange – Whether to arrange groups by their edges (True) or in sorted order of their values (False).

Returns:

pandas.DataFrame with one row per node, indexed by node id, in the network wide node order, with the column attribute (index with attribute = None), the position of the node, and, in bipartite networks, the column axis ("row" or "column").

Raises:

  • KeyError – If an attribute does not exist.

  • ValueError – If order is neither "degree" nor a numeric node attribute, or column criteria are given for a network that is not bipartite.

Example:

import graphoskop as gsk
import matplotlib.pyplot as plt

net = gsk.load_network("edges.tsv", "nodes.tsv")
pos = gsk.matrix_layout(net, "community")["matrix"]     # communities as diagonal blocks
edges = [(pos[a], pos[b]) for a, b in net.edges(None, labels = True)]
plt.scatter([b for a, b in edges] + [a for a, b in edges], [a for a, b in edges] + [b for a, b in edges], s = 1, marker = "s")
plt.gca().invert_yaxis()

gsk.matrix_layout(bip, order = "degree", column_order = "degree", descending = True)   # nested
gsk.matrix_layout(bip, ["country", "city"], column_groups = "sector", column_order = "size")

Transforming layouts

Positions computed by any layout can be mirrored, rotated and zoomed (along both axes or one of them) around the center of the drawing, either in the node attributes of the network or in the table a layout function returned. Nodes drawn as disks of a given size can be moved apart until none overlap, keeping the arrangement of the layout.

import graphoskop as gsk

net = gsk.load_network("edges.tsv")
gsk.hierarchical_layout(net)              # positions in pos_x, pos_y
gsk.mirror_layout(net, "y")               # root at the bottom
gsk.rotate_layout(net, -90)               # clockwise: root on the left
gsk.scale_layout(net, 0.5, axis = "y")    # half as tall
gsk.remove_overlaps(net, 0.3)             # disks of diameter 0.3 do not overlap

graphoskop.remove_overlaps(layout, size=1.0, margin=0.0, attribute='pos', max_iter=1000)

Remove the overlaps between nodes drawn as disks (spheres in three dimensions), moving them as little as possible and keeping their relative positions, with the proximity stress model PRISM (Gansner and Hu, 2010).

Pushing overlapping nodes apart creates new overlaps with their neighbors, and pushing those in turn spreads distortions; PRISM moves all nodes at once instead, keeping the layout’s structure. The neighbors of every node are the edges of the Delaunay triangulation of the positions (the proximity graph): every proximity edge whose two disks overlap gets a desired length longer than its current one by the factor that would remove the overlap (at most 1.5 at a time), every other edge its current length, and the layout is moved to the positions that best fit these lengths (stress majorization: least squares on the relative positions, weighted by the inverse squared lengths, solved by conjugate gradients). So nodes move apart where they overlap and their surroundings follow, with distances and orientations between neighbors kept as far as possible. The triangulation is recomputed and the steps repeated until no proximity edge overlaps; then pairs that still overlap without being neighbors in the triangulation are added to the proximity graph until no two disks overlap. Overlapping edges aim 5% beyond the overlap, which avoids a long tail of ever smaller pushes. The center of the layout does not move.

The result is not the layout with the smallest total displacement, which would let overlapping groups squeeze through each other, but the one that removes overlaps with the least distortion of the arrangement (no node jumps across another). Nodes at the same position are first set apart by a tiny random offset (fixed seed).

Parameters:

  • layout – A Network with positions in node attributes (changed in place), or a table of positions as returned by the layout functions (a new table is returned).

  • size – Diameter of the nodes, in layout units: a number for all nodes, the name of a numeric node attribute (with a network), or one value per node (an array or a pandas.Series indexed by node id).

  • margin – Smallest empty space left between two nodes.

  • attribute – With a network, the prefix of the position attributes.

  • max_iter – Most rounds of triangulation and stress majorization; a warning says if overlaps remain after them.

Returns:

pandas.DataFrame of the new positions, as the layout functions return.

Raises:

  • KeyError – If the network has no positions with that prefix, or no such size attribute.

  • ValueError – If sizes are negative or missing.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv")
gsk.force_directed_layout(net)
gsk.remove_overlaps(net, 0.5)                    # disks of diameter 0.5 (edges ~1 long)
gsk.remove_overlaps(net, "degree_size", margin = 0.05)

UMAP

UMAP lays out nodes so that those with similar vectors end up close. The vectors can be numeric node attributes, node embeddings computed on the fly, or the rows of the adjacency matrix, in which case the edges of the network are the neighbor graph that UMAP keeps, and the result is a force-directed layout with UMAP’s forces. graphoskop has its own implementation, in PyTorch, so it runs on the device of the network and adds no dependency; its neighbor graph matches the one of the umap-learn package to float precision, and its layouts score as well on trustworthiness and on nearest neighbor classification of known groups (handwritten digits, Gaussian blobs).

import graphoskop as gsk

net = gsk.lfr_benchmark_graph(2000, 10, 50, 0.2, minc = 20, maxc = 100, seed = 4)
gsk.umap_layout(net, seed = 0)                               # adjacency matrix
gsk.node2vec(net, 64, seed = 0, attribute = "emb")
gsk.umap_layout(net, "emb", metric = "cosine", attribute = "pos_n2v")

To follow a network over time, pass the layout of the previous snapshot as initial: nodes that were already there start at their old positions and are held near them (more firmly with a larger alignment), new nodes start next to their neighbors, and the layout changes only as much as the new edges and nodes require (aligned UMAP).

pos_2024 = gsk.umap_layout(gsk.load_network("edges_2024.tsv"), seed = 0)
net_2025 = gsk.load_network("edges_2025.tsv")
pos_2025 = gsk.umap_layout(net_2025, initial = pos_2024, seed = 0)
graphoskop.umap_layout(net, attributes=None, embedding=None, dimensions=2, n_neighbors=15, min_dist=0.1, metric='euclidean', weight=None, epochs=None, seed=None, attribute='pos', progress=None, initial=None, alignment=0.1)

Layout by UMAP (uniform manifold approximation and projection, McInnes, Healy and Melville, 2018): nodes with similar vectors end up close, and groups of similar nodes form separate clusters. The vectors can be numeric node attributes, node embeddings learned from the network, or the network itself:

  • attributes given: the vectors are those node attributes (for instance an embedding already stored with attribute = "emb" by node2vec(), or any numeric node attributes);

  • embedding given: the vectors are computed first, by a node embedding function of graphoskop given by name ("node2vec", "laplacian_eigenmaps", "gae", …: called with its defaults and seed) or by any function taking the network and returning one row per node (a pandas.DataFrame, array or tensor), for instance lambda net: gsk.node2vec(net, dimensions = 32, q = 2);

  • neither: UMAP runs on the adjacency matrix itself, taking the edges of the network as its neighbor graph (memberships proportional to weight, the largest being 1), which makes it a force-directed layout with UMAP’s attraction and repulsion.

With vectors, the neighbor graph links every node to its n_neighbors - 1 nearest nodes (the node itself counts as a neighbor, as in umap-learn; exact search, in chunks, on the device of the network: quadratic in the number of nodes), with memberships \(\exp(-(d - \rho) / \sigma)\), where \(\rho\) is the distance to the nearest neighbor and \(\sigma\) makes the memberships of each node sum to \(\log_2\) n_neighbors; the two directions of a pair are merged by the fuzzy union \(w_{uv} + w_{vu} - w_{uv} w_{vu}\).

The layout starts from pivot multidimensional scaling of each connected component of the neighbor graph, the components packed side by side (as in force_directed_layout()), then follows UMAP’s optimization: in every epoch each edge is sampled with probability equal to its membership and pulls its ends together with the gradient of \(\log(1 + a d^{2b})\), and each sampled edge pushes its first end away from 5 random nodes; \(a\) and \(b\) are fit so that similarity in the layout is about 1 up to min_dist and decays exponentially beyond. All the moves of an epoch are applied at once, as GPU implementations do (the reference implementation moves nodes one edge at a time), so results agree with the umap-learn package in quality, not point by point. The total move of a node in an epoch is clipped as a single move is (4 per coordinate, times the learning rate): otherwise the thousands of moves of a hub, summed, could throw it far from the rest, where UMAP’s attraction, which weakens with distance, cannot bring it back.

Aligned layouts (initial): to follow a network that changes over time, give the positions of the previous snapshot, as in aligned UMAP. Nodes that have one start there and, at every epoch, are pulled back towards it by alignment times their distance from it (times the learning rate), so they move only as much as the new edges and nodes require; new nodes start at the mean of their neighbors that have a position (spreading one hop per round, with a small random offset), and parts of the network with no such node start beside the old layout. On a 2,000-node network with 10% of its edges rewired and 300 new nodes, old nodes moved by a median 33% of the width of the layout when laid out again from scratch, 16% with alignment = 0.01, 5.5% with 0.1 and 2% with 1, groups staying as compact. Previous positions should be in the scale of UMAP layouts (as given by this function).

Unlike force_directed_layout(), distances between clusters carry little meaning (groups with few edges to the rest can drift far from it), and positions are left as UMAP produces them (no rescaling or packing at the end).

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • attributes – Names of numeric node attributes, or a prefix p selecting the attribute p or the attributes p_0, p_1, … (as stored by the embedding functions); None to use embedding or the adjacency matrix.

  • embedding – Name of a node embedding function of graphoskop, or a function of the network returning one vector per node in the network wide node order; ignored if attributes is given.

  • dimensions – 2 (pos_x, pos_y) or 3 (also pos_z).

  • n_neighbors – Number of neighbors of every node in the neighbor graph of the vectors: smaller values keep finer local structure, larger ones more of the global structure.

  • min_dist – Smallest distance between nodes in the layout, roughly: smaller values pack clusters tighter.

  • metric – Distance between vectors, "euclidean" or "cosine".

  • weight – Without vectors, name of a numeric edge attribute giving the strength of the edges, or None.

  • epochs – Number of epochs; None is 500 for networks up to 10,000 nodes, 200 above (as umap-learn).

  • seed – Seed of the pivots, of the edge sampling and of the negative samples (and of the embedding function).

  • attribute – Prefix of the numeric node attributes where to store the positions, or None to only return them.

  • progress – Whether to show a progress bar (see Progress bars); None uses the global setting.

  • initial – Previous positions: the prefix of numeric node attributes <initial>_x, <initial>_y (and <initial>_z; missing values for nodes without one), or a table indexed by node id with one column per dimension (such as the output of this function on the previous snapshot; ids not in the network are ignored); None for a new layout.

  • alignment – With initial, how strongly nodes are held at their previous positions: 0 only starts them there, larger values move them less.

Returns:

pandas.DataFrame with one row per node, indexed by node id, in the network wide node order, and one column per dimension.

Raises:

  • ValueError – If dimensions is not 2 or 3, the vectors do not have one row per node or have missing values, the metric is unknown, or initial does not have one column per dimension.

  • KeyError – If an attribute does not exist.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv")
gsk.umap_layout(net)                                   # UMAP of the adjacency matrix
gsk.umap_layout(net, embedding = "node2vec", seed = 0) # UMAP of node2vec vectors
gsk.node2vec(net, 64, attribute = "emb")
gsk.umap_layout(net, "emb", metric = "cosine")         # stored vectors emb_0 ... emb_63
gsk.umap_layout(net, ["age", "income"], attribute = "pos_attr")

pos = gsk.umap_layout(gsk.load_network("edges_2024.tsv"), seed = 0)
net = gsk.load_network("edges_2025.tsv")
gsk.umap_layout(net, initial = pos, seed = 0)          # aligned with the 2024 layout
