Networks and their attributes

Network container, loading of networks from edge list and node attribute tables, conversion back to tables, and saving to disk.

Node attributes are either numeric or qualitative. Numeric attributes are stored in the node_attr tensor of each component, on the device of the network. Qualitative attributes (strings, categories, any non-numeric value) are stored once for the whole network in Network.qualitative_node_attr, a pandas.DataFrame that always stays in CPU memory, whatever the device.

A network loaded with bipartite = True has two node types, given by the mandatory node attribute BIPARTITE, and no edge between two nodes of the same type.

A network loaded with multilayer = True is stored as its supra-graph: every node is a copy of an entity in one layer, with input id (entity, layer), and intra-layer edges, couplings (interlayer edges between copies of the same entity) and other interlayer edges are all ordinary edges (see Multilayer networks).

graphoskop.load_network(edges, nodes=None, sep='\t', header=True, source=0, target=1, edge_attributes=True, directed=False, node_format='wide', bipartite=False, device='cpu', multilayer=False, layer='layer', interlayer_edges=None, coupling=None, coupling_weight=1, layers=None)

Load a network from an edge list and a node attribute table, given as files or as pandas.DataFrame.

Node ids can be arbitrary strings. Ids read from files are strings; ids in a DataFrame are kept as they are, so the edge and node tables must use the same type (e.g. both int). DataFrames are not modified, and their column names play the role of the header row. Nodes are split by weakly connected component and remapped to (component, index), with index from 0 to n - 1. Nodes appearing only in the node table become isolated components. In undirected networks every edge is stored in both directions (input edges first, then their reverses, self loops once), following the torch_geometric convention. Every component has an edge_attr and a node_attr tensor, with zero columns when there are no such attributes. Only numeric edge attributes are stored.

Node attributes whose values are all numbers (or booleans) are numeric, and are stored in node_attr on device. The others are qualitative, and are stored in Network.qualitative_node_attr, always in CPU memory. In long format, this is decided for each attribute name: one non-numeric value makes the attribute qualitative.

A node can have several values of a qualitative attribute, e.g. overlapping communities (see Several values per node: overlapping communities): in long format, as several rows with the same node and attribute (which makes the attribute qualitative, even with numeric values; integer values stay integers); in a wide DataFrame, as a list, tuple or set in the cell. They are stored as a tuple of the distinct values.

With bipartite = True, the node table must give every node, isolated ones included, a value of the BIPARTITE attribute ("bipartite_type"), with at most two distinct values overall. The smaller value (in sort order) is type 0, the other type 1, as recorded in Network.bipartite_labels. BIPARTITE is always stored as a qualitative attribute, whatever its values. In every component, nodes of type 0 come first (see Network). Edges can join nodes in any column order and, if directed, go from either type to the other.

With multilayer = True (see Multilayer networks), every node is a copy of an entity in one layer, with input id (entity, layer):

  • the edge table needs a layer column (name or position given by layer): each edge joins the copies of its two entities in that layer;

  • interlayer_edges (file or DataFrame, same sep and header) gives interlayer edges by position: source, source layer, target, target layer, then edge attributes (matched by name with those of the edge table; missing ones are NaN). An interlayer edge between the two layers of the same entity is a coupling;

  • coupling generates couplings between the copies of every entity: "all" (every pair of copies; a warning is issued if they outnumber the intra-layer edges), "ordinal" (copies in adjacent layers only, undirected) or "temporal" (from each copy to the copy in the next layer, if any: forward in time only, so it needs directed = True). Layers are adjacent in the layer order: an entity without a copy in a layer is not coupled across it, but a layer with no node at all exists only if declared in layers (e.g. time steps 1, 2, 4 without layers make 2 and 4 adjacent). In directed networks "all" and "ordinal" couplings are stored in both directions. Couplings already given in interlayer_edges are not added again. Generated couplings get coupling_weight (a positive number, or a matrix with one value per pair of layers, in layer order) in every edge attribute;

  • the node table (if any) has the entity in the first column and the layer in the second, then the attributes (wide), or the attribute name and the value (long). Each row is a copy; copies appearing only there have no edges. A row with a missing layer applies to all the copies of its entity (those with edges or with their own rows), and the rows of a copy override it, so entity-wide attributes (e.g. BIPARTITE) are given once. A long row with a missing attribute only declares the copy;

  • layers are ordered by their values (parsed as numbers when possible), or as given in layers, which also lets layers without nodes exist. The order matters for ordinal and temporal couplings and is recorded in Network.layer_labels.

A bipartite multilayer network must be bipartite in every layer; all the copies of an entity have the same type, and interlayer edges must join nodes of the same type.

Parameters:

  • edges – Edge list, as a file path or a pandas.DataFrame.

  • nodes – Node attribute table, as a file path or a pandas.DataFrame, or None.

  • sep – Column separator of both files (ignored for DataFrames).

  • header – Whether both files have a header row (ignored for DataFrames).

  • source – Name or position of the source node column.

  • target – Name or position of the target node column.

  • edge_attributes – Whether to load the remaining edge columns as edge attributes.

  • directed – Whether the edges are directed.

  • node_format – "wide" (node id, then one column per attribute; numeric attributes stored as a dense node_attr) or "long" (node id, attribute name, value; numeric attributes stored as a sparse CSR node_attr).

  • bipartite – Whether the network is bipartite, with node types given by BIPARTITE.

  • device – Device where all tensors are created, e.g. "cuda". Qualitative attributes stay in CPU memory.

  • multilayer – Whether the network is multilayer.

  • layer – Name or position of the layer column of the edge table, in multilayer networks.

  • interlayer_edges – Interlayer edges, as a file path or a pandas.DataFrame, or None.

  • coupling – "all", "ordinal", "temporal" or None (no generated couplings).

  • coupling_weight – Value of every edge attribute of the generated couplings: a positive number, or an L by L matrix indexed by layer positions.

  • layers – Order of the layers, or None for their sort order.

Returns:

The loaded Network.

Raises:

ValueError – In bipartite networks, if there is no node table or no BIPARTITE attribute, if it has more than two distinct values, if a node has no type or two different ones (ids must be unique across node types), or if an edge joins two nodes of the same type. In multilayer networks, if there is no layer column, if an edge has no layer, if a layer is not in layers or layers cannot be sorted, if an interlayer edge joins two nodes of the same layer, if the coupling or its weight is not valid, if "temporal" coupling is asked for an undirected network, if a node attribute is named "layer", or, in bipartite multilayer networks, if an interlayer edge joins nodes of different types or the copies of an entity have different types. If interlayer_edges, coupling or layers are given without multilayer = True.

Examples:

import graphoskop as gsk

# tab separated, headers, first two columns are source and target
net = gsk.load_network("edges.tsv", "nodes.tsv")

# comma separated, named endpoint columns, directed
net = gsk.load_network("edges.csv", "nodes.csv", sep = ",", source = "from", target = "to", directed = True)

# no headers, no edge attributes, node table in long format
net = gsk.load_network("edges.tsv", "nodes.tsv", header = False, edge_attributes = False, node_format = "long")

# everything on the GPU (except qualitative node attributes)
net = gsk.load_network("edges.tsv", "nodes.tsv", device = "cuda")

# from DataFrames, node table in long format (id, attribute name, value)
import pandas as pd
edges = pd.DataFrame({"from": ["alice", "bob"], "to": ["bob", "carol"], "weight": [1.5, 2.0]})
nodes = pd.DataFrame({"id": ["alice", "carol"], "attribute": ["age", "city"], "value": [34, "Rome"]})
net = gsk.load_network(edges, nodes, source = "from", target = "to", node_format = "long")

# bipartite: users and the items they bought
edges = pd.DataFrame({"user": ["u1", "u1", "u2"], "item": ["i1", "i2", "i1"]})
nodes = pd.DataFrame({"id": ["u1", "u2", "i1", "i2", "i3"], "bipartite_type": ["user", "user", "item", "item", "item"]})
net = gsk.load_network(edges, nodes, bipartite = True)
net.bipartite_labels                 # ("item", "user"): items are type 0
n0 = net.bipartite_split[0]          # items of component 0 are nodes 0 to n0 - 1

# multiplex: friendship and work layers, all copies of each person coupled
edges = pd.DataFrame({"source": ["a", "b", "a"], "target": ["b", "c", "c"], "layer": ["friends", "friends", "work"]})
nodes = pd.DataFrame({"id": ["a", "d"], "layer": [None, "work"], "age": [30, 41]})
net = gsk.load_network(edges, nodes, multilayer = True, coupling = "all", coupling_weight = 0.5)
net.node_map[("a", "work")]          # (component, index) of the copy of "a" in layer "work"

# temporal network: snapshots 1, 2, 3, couplings forward in time
net = gsk.load_network("contacts.tsv", multilayer = True, layer = "time", coupling = "temporal", directed = True)
graphoskop.save_network(net, prefix, sep='\t', node_format=None, pickle=False, warn_size=100000000.0, max_size=1000000000.0)

Write a network to disk, as an edge table and a node table, or as a Python object.

The edge table goes to prefix + "_edges.tsv" and, if there are node attributes, the node table to prefix + "_nodes.tsv" (.csv instead of .tsv if sep is not a tab). Both have a header row, and are written as by Network.to_pandas_dataframes(): edges with columns source, target and their attributes, nodes in the network wide node order. Values containing the separator, a quote or a line break are quoted, following the CSV standard. All numeric and qualitative attributes are written, so the files load back with load_network(), passing the same sep, node_format, directed and bipartite (a bipartite network writes BIPARTITE for every node, and loads back as bipartite). Ids and qualitative values that look like numbers are read back as numbers.

The node table can be written in either format, whatever the format of net. In long format, a numeric value that is missing (NaN) in a wide table is left out, and so reads back as 0. In wide format, numeric values absent from a long table are written as 0.

A node with several values of an attribute (see Several values per node: overlapping communities) gets one row per value in a long table, which loads back as several values. A wide table cannot hold them: the long format is then the default, and asking for the wide one raises ValueError.

A multilayer network also writes its interlayer edges (couplings included) to prefix + "_interlayer.tsv", and always writes the node table (one row per copy, with the entity and the layer). The files load back with multilayer = True, interlayer_edges = prefix + "_interlayer.tsv" and the same directed, node_format and bipartite, without coupling.

The size of the node table file is estimated in both formats from a sample of nodes, before writing anything. If it is expected above warn_size bytes in the chosen format, a warning is issued. If moreover the chosen format is not the smaller one (wide with many attributes and few values per node, or long with dense attributes) and the file is expected above max_size bytes, ValueError is raised and nothing is written. A node table that is large in both formats is always written in the smaller one, with a warning.

With pickle = True, the Network object is written as it is to prefix + ".pt" with torch.save(), tensors on their current device, and is read back with load_pickled_network().

Parameters:

  • net – A Network.

  • prefix – Path and file name prefix, e.g. "data/flights".

  • sep – Column separator, e.g. "\t", ",", ";" or " ".

  • node_format – "wide" or "long" node table, or None for the format of net (long if some node has several values of an attribute).

  • pickle – Write the Python object instead of tables.

  • warn_size – Expected size in bytes of the node table above which a warning is issued.

  • max_size – Expected size in bytes of the node table, in the larger of the two formats, above which nothing is written.

Raises:

ValueError – If node_format is not valid, if it is "wide" and some node has several values of an attribute, or if the node table would be larger than max_size in the chosen format and smaller in the other one.

Example:

import graphoskop as gsk

net = gsk.load_network("purchases.tsv", "nodes.tsv", bipartite = True)
gsk.save_network(net, "out/purchases")                  # out/purchases_edges.tsv, out/purchases_nodes.tsv
net = gsk.load_network("out/purchases_edges.tsv", "out/purchases_nodes.tsv", bipartite = True)

gsk.save_network(net, "out/purchases", sep = ",", node_format = "long")   # .csv files
net = gsk.load_network("out/purchases_edges.csv", "out/purchases_nodes.csv", sep = ",", node_format = "long", bipartite = True)

gsk.save_network(net, "out/purchases", pickle = True)   # out/purchases.pt
net = gsk.load_pickled_network("out/purchases.pt")

net = gsk.load_network("multiplex.tsv", multilayer = True, coupling = "all")
gsk.save_network(net, "out/multiplex")                  # _edges.tsv, _interlayer.tsv, _nodes.tsv
net = gsk.load_network("out/multiplex_edges.tsv", "out/multiplex_nodes.tsv", multilayer = True, interlayer_edges = "out/multiplex_interlayer.tsv")

class graphoskop.Network(components, node_map, node_ids, node_attributes, edge_attributes, directed, qualitative_node_attr, qualitative_node_attributes, node_format='wide', bipartite_labels=None, bipartite_split=None, layer_labels=None, entity_ids=None)

A network split into its weakly connected components.

Nodes are ordered network wide by component, then by index within the component: component c holds the positions node_offsets[c] to node_offsets[c + 1] - 1 of this order. In bipartite networks, the nodes of type 0 come first in every component: node i of component c has type 0 if i < bipartite_split[c], type 1 otherwise. The biadjacency matrix of a component then has rows 0 to bipartite_split[c] - 1 and columns bipartite_split[c] to n - 1, and the attributes of each type are a slice of the node tables.

Variables:

  • components – One torch_geometric.data.Data per weakly connected component, sorted by number of nodes in descending order (component 0 is the largest).

  • node_map – Maps each input node id to its internal id (component, index).

  • node_ids – For each component, the array of input node ids ordered by internal index.

  • node_offsets – Position of the first node of each component in the network wide node order, followed by the number of nodes.

  • node_attributes – Numeric node attribute names, in order of appearance in the node table; position j is column j of node_attr.

  • qualitative_node_attributes – Qualitative node attribute names, in order of appearance in the node table. A name is never in both lists.

  • qualitative_node_attr – Qualitative node attributes, in CPU memory. In wide format, one categorical column per attribute and one row per node, in the network wide node order. In long format, columns node (position in the network wide node order), attribute and value (both categorical), one row per stored value.

  • node_format – "wide" or "long", the format of the node table.

  • edge_attributes – Numeric edge attribute names; position j is column j of edge_attr.

  • directed – Whether the edges are directed.

  • bipartite_labels – In bipartite networks, the values of BIPARTITE of type 0 and type 1, in this order (sorted); None otherwise.

  • bipartite_split – In bipartite networks, the number of nodes of type 0 of each component; None otherwise.

  • layer_labels – In multilayer networks, the layers in their order (sorted, or as given to load_network()); None otherwise. Each component then also has the int64 tensors layer (position of the layer of each node in layer_labels) and entity (position of its entity in entity_ids), on its device. Within each component, nodes are sorted by layer (by type first, then by layer, in bipartite networks).

  • entity_ids – In multilayer networks, the input ids of the entities; None otherwise.

  • entity_map – In multilayer networks, maps each entity to the list of the internal ids (component, index) of its copies, in layer order; None otherwise.

Example, reading and setting attributes by name:

age = net.get_node_attribute("age")             # vector over the nodes of component 0
city = net.get_node_attribute("city")           # qualitative: NumPy array, on the CPU
c, i = net.node_map["alice"]
age_alice = net.get_node_attribute("age", c)[i]
w = net.get_edge_attribute("weight")            # vector over the edges of component 0
w_ab = net.get_edge_attribute("weight", edge = ("alice", "bob"))   # one edge, None if absent
net.set_edge_attribute("log_weight", w.log())   # new attribute, NaN in other components
net.set_node_attribute("age", [a + 1 for a in net.get_node_attribute("age", None)], None)
net.set_node_attribute("group", ["a"] * net.number_of_nodes(0))   # new qualitative attribute
net.number_of_nodes(), net.number_of_edges(), net.number_of_components()

get_node_attribute(key, component=0)

Node attribute as a vector over the nodes of a component.

Numeric attributes work for both wide (dense) and long (sparse) node tables; in the latter, nodes without a value for the attribute get 0. The vector is a copy, ordered by internal node index, on the device of the component. Qualitative attributes are returned as a NumPy object array, with NaN for missing values.

Parameters:

  • key – Attribute name, or position in node_attributes.

  • component – Index of the component (0 is the largest), or None for all components.

Returns:

Vector of length n, or a list of them if component is None.

Raises:

KeyError – If there is no node attribute with that name.

set_node_attribute(key, values, component=0)

Set a node attribute on the nodes of a component, creating it if it does not exist.

A new attribute is numeric if its values are (a torch.Tensor, or an array or list of numbers or booleans), qualitative otherwise. A new numeric attribute is appended to node_attributes and to node_attr of every component; components not set get NaN (wide, dense tables) or no value, read as 0 (long, sparse tables). In sparse tables, zero values are not stored. Values are cast to the dtype of node_attr. A new qualitative attribute is appended to qualitative_node_attributes; components not set get NaN (missing). A node can have several values of a qualitative attribute, given as a list, tuple or set (see Several values per node: overlapping communities).

Parameters:

  • key – Attribute name, or position in node_attributes.

  • values – Vector of length n, ordered by internal node index, or a list of them (one per component) if component is None.

  • component – Index of the component (0 is the largest), or None for all components.

Raises:

  • KeyError – If key is a position and there is no node attribute there.

  • ValueError – If a vector does not have one value per node, if non-numeric values are given for a numeric attribute, if key is BIPARTITE in a bipartite network (node types fix the node order and cannot change), or if key is "layer" in a multilayer network (the layer is part of the node id).

get_edge_attribute(key, component=0, edge=None)

Edge attribute as a vector over the edges of a component, or its value on one edge.

The vector is a copy, aligned with the columns of edge_index, on the device of the component. In undirected networks every edge is stored in both directions, so each value appears twice (self loops once), as in edge_attr.

With edge = (u, v), given by input node ids, the value on the edge between u and v is returned instead, as a Python number, and component is ignored. In directed networks the edge goes from u to v; in undirected networks the order does not matter. If the edge is not in the network (including when a node is not), None is returned. If there are parallel edges, the list of their values is returned, in input order.

Parameters:

  • key – Attribute name, or position in edge_attributes.

  • component – Index of the component (0 is the largest), or None for all components.

  • edge – Pair of input node ids (u, v), or None.

Returns:

Vector with one entry per stored edge, or a list of them if component is None; with edge, a number, a list of numbers or None.

Raises:

KeyError – If there is no edge attribute with that name.

is_planar(component=None)

Whether the network is planar: whether it can be drawn on the plane without edge crossings.

Left-Right planarity test (de Fraysseix and Rosenstiehl, 1982; Brandes, 2009), linear in the size of each component, in plain Python on the CPU (about 10 seconds for 600,000 edges). Edge directions, self loops, parallel edges and weights do not matter. A network is planar if all its components are. In multilayer networks the test is on the supra-graph, interlayer edges included (a layer alone is tested on layer_network()).

Parameters:

component – Index of the component (0 is the largest), or None for the whole network.

Returns:

True if planar.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv")
net.is_planar()
net.is_planar(component = 0)   # largest component only
to_pandas_dataframes()

Edges and nodes of all components, with their attributes, as pandas.DataFrame.

The edge table has columns source and target (input node ids), then one column per edge attribute. Edges are grouped by component, in input order within each component. In undirected networks each edge appears once, as in the input (the reverse copies stored by load_network() are dropped).

The node table is returned only if there are node attributes (always in bipartite networks, which have BIPARTITE). Nodes are in the network wide node order. Wide node tables give a node column, then one column per numeric attribute, then one (categorical) column per qualitative attribute, with a row for every node and NaN for missing values. Long node tables give columns node, attribute and value, with a row for every stored value (numeric values first). Both tables can be passed back to load_network(), with the same node_format and bipartite. Nodes without edges are kept only in the node table, so they are lost if there are no node attributes.

Multilayer networks always give three tables, (edges, interlayer, nodes), which load back with multilayer = True and interlayer_edges = interlayer (and no coupling: the couplings are in interlayer):

  • edges: intra-layer edges, with columns source, target (entities), layer, then the edge attributes;

  • interlayer: interlayer edges (couplings included), with columns source, source_layer, target, target_layer, then the edge attributes;

  • nodes: one node per copy, with columns node (entity) and layer, then the attributes as above. In long format, a copy without any value gets a row with a missing attribute and value, so that copies without edges are not lost.

Returns:

The edge table, or (edges, nodes) if there are node attributes, or (edges, interlayer, nodes) for multilayer networks.

Raises:

ValueError – If an attribute is named like one of the id columns.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
gsk.noise_corrected(net)
edges, nodes = net.to_pandas_dataframes()
edges.to_csv("scored_edges.tsv", sep = "\t", index = False)

Numeric and qualitative node attributes

Numeric node attributes live in the node_attr tensor of each component, on the device of the network, and are what Laplacian solvers and node vector analysis work on. Qualitative node attributes (strings, categories) cannot be used by these computations, so they never take GPU memory: they are kept once for the whole network in Network.qualitative_node_attr, a pandas.DataFrame of categorical columns in CPU memory, with rows in the network wide node order (component by component). Both kinds are read and written by name with get_node_attribute() and set_node_attribute(), and are kept by extract_backbone() and spanning_tree().

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv", device = "cuda")
net.node_attributes               # ["age", "height"]: on the GPU
net.qualitative_node_attributes   # ["city"]: in CPU memory
net.get_node_attribute("city")    # NumPy object array over the nodes of component 0

Several values per node: overlapping communities

A qualitative node attribute can give a node several values, e.g. the communities of a node in more than one. In Python, the value of such a node is a list, tuple, set or array of values; it is stored as a tuple of its distinct values (in order, sorted for sets), and a collection of one value as that value, so that nodes in one community keep a plain label. Strings are single values. A numeric attribute cannot take several values: use a new attribute name.

In files, several values are several rows of a long node table (node_format = "long"), one per value: the rows of a node and attribute are merged into a tuple on loading, and tuples are written back as several rows by save_network(). A wide table, with one cell per node and attribute, cannot hold them: saving them in wide format raises an error (save in long format, or pickle the network). Numeric labels read from a long table stay integers when they all are.

modularity() switches to overlapping modularity for such partitions, and mixed_membership_block_model() generates and randomizes networks with overlapping communities. Functions that need one value per node, e.g. categorical assortativity() or the other blockmodels, raise ValueError.

net.set_node_attribute("community", [[0, 1], 1, {1, 2}, (2,)])   # stored as (0, 1), 1, (1, 2), 2
gsk.modularity(net, "community")                                  # overlapping (Shen et al.)
gsk.save_network(net, "out", node_format = "long")                # node 0: two "community" rows

Bipartite networks

A bipartite network is loaded with bipartite = True and a node table giving every node a value of the bipartite_type attribute, with two distinct values. Node ids must be unique across the two types. Loading fails if a node has no type, or two different ones, or if an edge joins two nodes of the same type.

The node types fix a canonical node order: in every component, nodes of type 0 (the smaller value of bipartite_type) come first, then nodes of type 1. With k = net.bipartite_split[c], nodes 0 to k - 1 of component c have type 0, so the biadjacency matrix is the block of rows 0 to k - 1 and columns k to n - 1 of the adjacency matrix, and the attributes of each type are the slices [:k] and [k:] of the node tables. The order is kept by every function returning a new network, and bipartite_type cannot be changed after loading. Unipartite networks of one node type are obtained with the functions in Bipartite projections.

import graphoskop as gsk

# nodes.tsv:   id   bipartite_type   price
#              u1   user
#              i1   item             9.5
net = gsk.load_network("purchases.tsv", "nodes.tsv", bipartite = True)
net.bipartite_labels                       # ("item", "user")
k = net.bipartite_split[0]
price = net.get_node_attribute("price")[:k]   # items of component 0

Multilayer networks

A multilayer network is loaded with multilayer = True from an edge table with a layer column. Nodes are then copies of entities in layers, with input ids (entity, layer), and couplings between the copies of an entity are generated with coupling = "all", "ordinal" or "temporal". See Multilayer networks.

import graphoskop as gsk

net = gsk.load_network("edges.tsv", multilayer = True, coupling = "all")
net.node_map[("alice", "work")]   # copy of alice in layer "work"
gsk.degree(net, "alice")          # summed over the layers of alice

Node ids

Functions taking nodes accept their input id or their internal id (component, index), and, in multilayer networks, an entity (all its copies). A tuple that is both an input id and a valid internal id (e.g. (0, 1) with integer entities and layers) raises ValueError: give the node by its input id. Ids read from files are strings, so a number is also tried as a string.
