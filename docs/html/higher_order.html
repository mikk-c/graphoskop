Higher-order networks

Hypergraphs and simplicial complexes: interactions among any number of nodes.

A hypergraph has nodes and hyperedges, each hyperedge a set of nodes of any size (a meeting and its participants, a paper and its authors). Two hyperedges can have the same nodes, and a hyperedge can have one node or none. A simplicial complex is a hypergraph closed under subsets: if a simplex (a set of nodes) is in it, so are all its faces (its non-empty subsets). A simplex of \(d + 1\) nodes has dimension \(d\): a filled triangle (dimension 2) implies its three edges and three nodes, but three edges do not imply the filled triangle. A complex is then given by its facets, the simplices that are not a face of another one.

Both are stored as bipartite networks, their incidence graphs: nodes (type 0, first in every component) linked to the hyperedges or facets they belong to (type 1). This takes memory proportional to the sum of the sizes of the hyperedges (the clique expansion grows with their squares), keeps everything (unlike any projection), and is the layout of torch_geometric.nn.HypergraphConv. The connected components of the incidence graph are those of the hypergraph. A simplicial complex stores its facets only, never its faces.

  • Ids. Nodes keep their ids. Hyperedges get ids Hyperedge(label) (Hyperedge), with the labels given in input or, without labels, their positions from 0. Facets get ids Simplex(nodes) (Simplex): a simplex is its set of nodes. These ids never equal a node id, so a node 3 and Hyperedge(3) can coexist. Both appear in node_map and node_ids.

  • Attributes. Nodes, hyperedges and facets have numeric and qualitative attributes, stored as node attributes (one table, shared names, values missing where not given): read and set them with get_node_attribute() (nodes only), get_hyperedge_attribute() and get_facet_attribute(), and their set_ counterparts. A membership (a node in a hyperedge) can carry attributes too, such as the position of an author or a weight of the node in the hyperedge: they are the edge attributes.

  • Directed hypergraphs. A directed hyperedge goes from its tail nodes to its head nodes: a tail membership is an edge from the node to the hyperedge, a head membership one from the hyperedge to the node.

  • Counts. number_of_nodes() counts the nodes only; number_of_hyperedges() and number_of_facets() the rest. edges() and number_of_edges() give the memberships.

Analyses. Run on the incidence graph, most functions of the library would answer the wrong question, without any warning: degrees and centralities would count hyperedges as nodes, path lengths would double, clustering would always be zero. So every function says in its documentation whether it supports hypergraphs and simplicial complexes, and raises ValueError when given one it does not support. To analyze the incidence graph anyway, pass incidence_network() (a plain bipartite network); for the network of nodes sharing a hyperedge, pass clique_expansion().

import graphoskop as gsk

net = gsk.load_hypergraph([["a", "b", "c"], ["b", "d"]])
net.number_of_nodes(), net.number_of_hyperedges()       # 4, 2
net.set_hyperedge_attribute("hours", [2., 1.])
g = gsk.clique_expansion(net)                           # a plain network of the nodes
gsk.degree(g, "b")                                      # 3: a, c and d
gsk.degree(net, "b")                                    # 2: the hyperedges of b
gsk.laplacian(net)                                      # Zhou's hypergraph Laplacian
gsk.local_clustering(net)                               # ValueError: not supported (yet)

sc = gsk.load_simplicial_complex([["a", "b", "c"], ["a", "b"], ["c", "d"]])
sc.number_of_facets()                                   # 2: {a, b} is a face of {a, b, c}

Attributes and counts

These methods of Network are for hypergraphs and simplicial complexes; get_node_attribute(), set_node_attribute() and number_of_nodes() cover their nodes only. The simplices of one dimension of a simplicial complex (its edges, its triangles, …) are listed by simplices(), enumerated from the facets when first asked for and cached.

A simplicial complex has three kinds of attributes: node attributes, facet attributes (a value of a facet as a whole, such as the date of a meeting) and simplex attributes, with a value on every simplex of one dimension, faces included (a flow on every edge, the area of every triangle). Simplex attributes are stored in one table per dimension, aligned with simplices(), and only for the dimensions that have them. Oriented values, such as flows, refer to the reference orientation of each simplex (its nodes in increasing internal index); a table of values given for other orientations is converted with oriented = True.

import graphoskop as gsk
import pandas as pd

net = gsk.load_simplicial_complex([["a", "b", "c"], ["c", "d"]])
flows = pd.DataFrame({"from": ["b", "d"], "to": ["a", "c"], "flow": [2., 5.]})
net.set_simplex_attribute(flows, dimension = 1, oriented = True)
net.get_simplex_attribute("flow")       # [-2, nan, nan, -5] over the edges ab, ac, bc, cd
net.simplex_attributes                  # {"flow": 1}

Network.set_simplex_attribute(key=None, values=None, dimension=None, component=0, oriented=False)

Set an attribute of the simplices of one dimension of a simplicial complex: values on its edges (flows, weights), triangles, and so on, faces of the facets included. Node values are node attributes (set_node_attribute()); a value of a facet as a whole (a meeting and its date) is a facet attribute (set_facet_attribute()). A simplex attribute has one dimension and values on all its simplices (missing where not given); its name is not shared with node or facet attributes. Only the dimensions with attributes are enumerated (see simplices()), never the whole complex.

Values are given as a vector over the simplices of the dimension of a component, aligned with simplices(), or as a table (pandas.DataFrame, wide format): its first dimension + 1 columns hold the nodes of a simplex, the other columns its attributes. With oriented, numeric values of the table are those of the simplex oriented as its nodes are listed, and are stored for the reference orientation (nodes in increasing internal index, as in simplices()): with a sign change if the two orders differ by an odd permutation, as for a flow from v to u given on the edge (v, u).

Simplex attributes are kept by save_network(), which writes those of dimension \(d\) to prefix + "_simplices_d.tsv" as such a table, in reference orientation (node_0, node_1, … then the attributes).

Parameters:

  • key – Attribute name; None for a table.

  • values – Vector over the simplices (torch.Tensor, numpy.ndarray or list; numeric or not), or a list of them if component is None; without key, the table.

  • dimension – Dimension of the simplices, at least 1; for an existing attribute, None or its dimension.

  • component – Index of the component (0 is the largest), or None for all components; ignored for a table.

  • oriented – Whether the numeric values of a table change sign with the orientation of their simplices.

Raises:

  • ValueError – If the network is not a simplicial complex, the dimension is missing or below 1, a vector has the wrong length, the name is a node attribute, a numeric attribute gets non-numeric values (or the reverse), or a table repeats a simplex or a node in a row.

  • KeyError – If a row of the table is not a simplex of the complex.

Example:

import graphoskop as gsk
import pandas as pd

net = gsk.load_simplicial_complex([["a", "b", "c"], ["c", "d"]])
net.set_simplex_attribute("width", [1., 2., 1., 3.], dimension = 1)   # the 4 edges
flows = pd.DataFrame({"from": ["b", "d"], "to": ["a", "c"], "flow": [2., 5.]})
net.set_simplex_attribute(flows, dimension = 1, oriented = True)
net.get_simplex_attribute("flow")       # [-2, nan, nan, -5]: a -> b and c -> d

graphoskop.incidence_network(net)

The incidence graph of a hypergraph or simplicial complex, as a plain bipartite network: the same nodes, hyperedges or facets (type 1, BIPARTITE "hyperedge" or "simplex"), memberships and attributes, with higher_order = None, so that every function of the library accepts it and treats hyperedges and facets as nodes. Generalized degrees

The degree of a node (degree()) is its number of hyperedges in a hypergraph and its number of edges in a simplicial complex. Simplicial complexes generalize it to every face: the generalized degree \(k_{d,m}\) of an \(m\)-simplex counts the \(d\)-simplices containing it (\(k_{1,0}\) is the degree), and the incidence number \(k_{d,d-1} - 1\) counts the \(d\)-simplices sharing a \((d - 1)\)-face beyond the first. Their values are over the \(m\)-simplices, in the order of simplices().

import graphoskop as gsk

net = gsk.load_simplicial_complex([["a", "b", "c", "d"], ["c", "d", "e"]])
gsk.degree(net, "c")                              # 4: the edges at c
gsk.generalized_degree(net, 2, 0, "c")            # 4: the triangles at c
gsk.generalized_degree(net, 2, 1, ["c", "d"])     # 3: the triangles on the edge {c, d}
gsk.incidence_number(net, 2, ["c", "d"])          # 2
graphoskop.generalized_degree(net, d, m=0, simplex=None, distribution='count', component=None, batch_size=16777216)

Generalized degree of the faces of a simplicial complex (Bianconi and Rahmede, 2016): the generalized degree \(k_{d,m}(\alpha)\) of an \(m\)-dimensional simplex \(\alpha\) is the number of \(d\)-dimensional simplices of the complex that contain it, for \(m < d\). Faces count: a tetrahedron facet brings its four triangles and six edges. So \(k_{1,0}\) is the degree of the nodes (degree()), \(k_{2,0}\) the number of triangles at a node, \(k_{2,1}\) the number of triangles on an edge. Faces in no \(d\)-simplex have 0.

  • simplex given: its generalized degree, as an int. A node id when m = 0; otherwise the collection of its nodes (list, tuple, set or Simplex).

  • simplex a list of them: a pandas.DataFrame with columns simplex (as given) and generalized_degree.

  • simplex = None: the distribution over all the \(m\)-simplices (columns generalized_degree and count, pdf or ccdf, as degree()).

  • simplex = None and distribution = None: an int64 vector over the \(m\)-simplices of the component, aligned with the rows of simplices() (a list of vectors if component is None), on the device of the network.

The \(d\)-simplices and the \(m\)-simplices are enumerated from the facets once and cached (see simplices()); each \(d\)-simplex then gives its \(\binom{d + 1}{m + 1}\) faces, matched to the \(m\)-simplices on the device, in batches of about batch_size. The number of simplices grows quickly with the size of the facets: a facet of \(s\) nodes has \(\binom{s}{d + 1}\) simplices of dimension \(d\).

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

Parameters:

  • net – A simplicial complex (load_simplicial_complex()).

  • d – Dimension of the counted simplices, at least 1.

  • m – Dimension of the faces whose generalized degree is computed, from 0 to d - 1.

  • simplex – Face, list of faces, or None.

  • distribution – "count", "pdf", "ccdf", or None for the value of every face; used when simplex is None.

  • component – For the distribution or the vectors, index of the component (0 is the largest), or None for the whole complex.

  • batch_size – Target number of (simplex, face) pairs matched at once.

Returns:

Generalized degree, pandas.DataFrame, or vector (list of vectors).

Raises:

  • ValueError – If net is not a simplicial complex, if not 0 <= m < d, if distribution is not valid, or if a face does not have m + 1 nodes.

  • KeyError – If a face is not a simplex of the complex.

Example:

import graphoskop as gsk

net = gsk.load_simplicial_complex([["a", "b", "c", "d"], ["c", "d", "e"]])
gsk.generalized_degree(net, 1, 0, "c")             # 4 edges at c: its degree
gsk.generalized_degree(net, 2, 1, ["c", "d"])      # 3 triangles on the edge {c, d}
gsk.generalized_degree(net, 3, 0, distribution = "pdf")
k = gsk.generalized_degree(net, 2, 1, distribution = None, component = 0)
edges = net.simplices(1, labels = True)           # the edges, aligned with k
graphoskop.incidence_number(net, d, simplex=None, distribution='count', component=None, batch_size=16777216)

Incidence number of the \((d - 1)\)-dimensional faces of a simplicial complex (Bianconi and Rahmede, 2016; the name is from Cinardi, Rapisarda and Bianconi, 2019): \(n_\alpha = k_{d,d-1}(\alpha) - 1\), the number of \(d\)-simplices sharing the face \(\alpha\) beyond the first (see generalized_degree()). A face in no \(d\)-simplex has \(n_\alpha = -1\) (the definition assumes pure complexes, made of \(d\)-simplices and their faces).

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

  • d – Dimension of the simplices sharing the faces, at least 1.

  • simplex – Face, list of faces, or None.

  • distribution – "count", "pdf", "ccdf", or None for the value of every face; used when simplex is None.

  • component – For the distribution or the vectors, index of the component (0 is the largest), or None for the whole complex.

  • batch_size – As in generalized_degree().

Returns:

Incidence number, pandas.DataFrame, or vector (list of vectors).

Raises:

  • ValueError – As generalized_degree().

  • KeyError – If a face is not a simplex of the complex.

Example:

Hodge Laplacians

The boundary matrix \(B_k\) maps every \(k\)-simplex to its faces, with signs from the order of their nodes; the Hodge Laplacian \(L_k = B_k^T B_k + B_{k+1} B_{k+1}^T\) acts on functions of the \(k\)-simplices (flows on edges for \(k = 1\)), and the dimension of its kernel counts the \(k\)-dimensional holes of the complex (its Betti number). The random walk of Schaub et al. (2020) moves on oriented edges; its average dynamics is the normalized Hodge 1-Laplacian. Rows and columns follow simplices().

import graphoskop as gsk
import torch

hollow = gsk.load_simplicial_complex([["a", "b"], ["b", "c"], ["a", "c"]])
L1 = gsk.hodge_laplacian(hollow, 1)
int((torch.linalg.eigvalsh(L1).abs() < 1e-6).sum())      # 1: one hole
gsk.simplicial_random_walk(hollow, ("a", "b"), 10, seed = 0)

Boundary matrix \(B_k\) of a simplicial complex: one row per \((k - 1)\)-simplex, one column per \(k\)-simplex, in the order of simplices(), with \((B_k)_{\tau \sigma} = (-1)^i\) if \(\tau\) is \(\sigma\) without its \(i\)-th node, 0 otherwise. Every simplex has the reference orientation given by the order of its nodes (internal indices, increasing): \(B_1\) gives each edge \([u, v]\), \(u < v\), the entries \(-1\) at \(u\) and \(+1\) at \(v\), and \(B_k B_{k + 1} = 0\).

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

Parameters:

  • net – A simplicial complex.

  • k – Dimension of the columns, at least 1.

  • component – Index of the component (0 is the largest).

  • sparse – Whether to return a sparse (COO) tensor instead of a dense one.

Returns:

float32 tensor on the device of the network.

Raises:

ValueError – If net is not a simplicial complex or k is below 1.

Example:

import graphoskop as gsk

net = gsk.load_simplicial_complex([["a", "b", "c"]])

graphoskop.hodge_laplacian(net, k, component=0, normalized=False, sparse=False)

Hodge Laplacian of the \(k\)-simplices of a simplicial complex, \(L_k = B_k^T B_k + B_{k + 1} B_{k + 1}^T\) (boundary_matrix(); the first term is absent for \(k = 0\), where \(L_0\) is the Laplacian of the 1-skeleton). Rows and columns follow simplices(). Its kernel has the dimension of the \(k\)-th homology of the complex (its \(k\)-dimensional holes), and it splits flows on \(k\)-simplices into gradient, curl and harmonic parts (Hodge decomposition).

graphoskop.simplicial_random_walk(net, source, length, walks=1, seed=None)

Random walks on the oriented edges of a simplicial complex (Schaub, Benson, Horn, Lippner and Jadbabaie, 2020), whose average dynamics is the normalized Hodge 1-Laplacian (hodge_laplacian() with normalized = True): it diffuses edge flows, and so sees the holes of the complex. At each step, with probability 1/2 each:

  • lower move: through the head of the current oriented edge (forward) or its tail (backward), with probability 1/2 each, to an oriented edge leaving (forward) or entering (backward) that node, the current edge reversed included, with probability proportional to \(\max(\deg, 1)\), \(\deg\) its number of triangles;

  • upper move: if the edge is in triangles, one of them uniformly, then, with probability 1/3 each, the edge reversed or one of the two other edges of the triangle, oriented opposite to the current one with respect to the triangle; if the edge is in no triangle, it stays or is reversed, with probability 1/2 each.

Homology

The Betti numbers count the holes of a simplicial complex in each dimension: \(\beta_0\) its connected components, \(\beta_1\) its loops that bound no surface, \(\beta_2\) its voids. They come from exact ranks of the boundary matrices, computed by sparse column reduction in compiled code; the Euler characteristic is their alternating sum, and the alternating sum of the numbers of simplices.

gsk.euler_characteristic(sphere)        # 2
graphoskop.betti_numbers(net, dimension=None, component=None)

Betti numbers of a simplicial complex: \(\beta_k\) counts its \(k\)-dimensional holes, \(\beta_0\) its connected components, \(\beta_1\) its loops that do not bound a surface (a hollow triangle has one, a filled one none), \(\beta_2\) its voids (a hollow tetrahedron, a sphere). They are the dimensions of the homology groups with real coefficients, \(\beta_k = n_k - \mathrm{rank} B_k - \mathrm{rank} B_{k + 1}\), with \(n_k\) the number of \(k\)-simplices and \(B_k\) the boundary matrices (boundary_matrix()), and equal the dimension of the kernel of the Hodge Laplacian \(L_k\) (hodge_laplacian()): the harmonic signals of hodge_decomposition().

The ranks are exact, not numerical: the sparse boundary matrices are reduced by column operations in compiled code, modulo the prime \(2^{31} - 1\) (equal to the rank over the reals unless the homology has torsion of that order, which no complex of a sane size has), from the highest dimension down, skipping the columns that a reduction of the dimension above shows to vanish (clearing; Chen and Kerber, 2011). Every simplex up to dimension dimension + 1 is enumerated (see simplices()), which limits this to complexes whose facets are not too large: a facet of \(m\) nodes has \(2^m - 1\) faces.

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

Returns:

List of the Betti numbers \(\beta_0, \beta_1, \ldots\).

Raises:

Example:

Paths with memory

Memory in sequences: networks whose nodes are a place together with some of the steps before it, built from paths (ships between ports, passengers between airports, users between web pages, the walks of random_walk()). In an ordinary network, a walker at c moves on the same way whatever it came from; here node c|b (at c, coming from b) has its own out edges. A memory network (Rosvall et al., 2014) has a node for every past of a fixed length; a higher-order dependency network (Xu, Wickramarathne and Chawla, 2016) only for the pasts that the data show to change the next step, of any length up to a maximum. Both are plain directed weighted networks: walks, PageRank, Laplacians and communities apply as they are, and first_order_values() gathers their results back over the places.

Hypergraphs and simplicial complexes describe interactions among several nodes at once. Paths carry another kind of higher order: memory, where the next step depends on the last few. Both models here keep it in an ordinary directed network of states (c|b: at c, coming from b), whose transition probabilities are those of the paths, so that a random walk on it reproduces their memory, and every walk-based analysis (PageRank, stationary distributions, Infomap, Laplacians) follows the paths more closely than on the first-order network.

  • memory_network() (Rosvall et al., 2014): a Markov chain of fixed order, every past of that length a state. With the teleportation of the paper, PageRank gives the flow through every place; Infomap with physical = "first_order_node" lets the states of a place share its codeword in a module, and places belong to several modules, as the flows through them do.

  • higher_order_dependency_network() (Xu, Wickramarathne and Chawla, 2016): pasts of varying length, each added only where the data show that it changes the next step.

import graphoskop as gsk

mem = gsk.memory_network("trajectories.txt")           # second order: states "k|j"
flow = gsk.first_order_values(mem, gsk.pagerank(mem, weight = "weight", personalization = "count"))
gsk.infomap_communities(mem, weight = "weight", physical = "first_order_node")
gsk.first_order_values(mem, "community", how = set)    # overlapping modules of the places

hon = gsk.higher_order_dependency_network("trajectories.txt", max_order = 5)
# files in the authors' format, "id node node ...": add labeled = True
hon.get_node_attribute("order")                       # 1 for the places, 2+ for their pasts
pr = gsk.first_order_values(hon, gsk.pagerank(hon, weight = "weight"))   # PageRank of the places

# a check against chance: walks without memory, about as many steps as the data
# (set walks and their length to match); higher-order nodes found here are spurious
fon = gsk.higher_order_dependency_network("trajectories.txt", max_order = 1)
walks = gsk.random_walk(fon, list(fon.node_ids[0]), 100, walks = 50, weight = "weight")
null = gsk.higher_order_dependency_network(walks, max_order = 5)

graphoskop.higher_order_dependency_network(sequences, max_order=5, min_support=1, sep=None, device='cpu', progress=None, labeled=False)

Higher-order network of a set of sequences (HON, Xu, Wickramarathne and Chawla, 2016), by the rule extraction and network wiring of the paper (Algorithms 1 and 2, as in the authors’ code).

  1. Observations. Every subsequence of the data is counted as a source (the last k steps, \(k \leq\) max_order) followed by a target (the next node). Pairs seen fewer than min_support times are dropped, and the rest give the next-step distribution \(P(\cdot | s)\) of every source \(s\).

  2. Rules. Starting from every node, a source is extended by one earlier step at a time. An extension \(s'\) is a new dependency if its distribution differs enough from that of the last valid source \(s\) it extends:

    \[D_{KL}(P(\cdot | s') \,\|\, P(\cdot | s)) > \frac{k'}{\log_2(1 + n(s'))},\]

    with \(k'\) the order of \(s'\) and \(n(s')\) the number of its observations: a higher order, or less data, needs a larger difference. Extensions that are not new dependencies are still followed, in case an even longer past matters.

  3. Wiring. Every valid source (and every source on its way, its prefixes) becomes a node, named after the reference code: the current node, |, then its past, most recent step first, steps separated by .: c| for node c, c|b for c coming from b, c|b.a for c after a then b (. is a separator, not a decimal point). Each of its observed next steps t becomes an edge to the longest node matching the end of the path (t|c.b if it exists, otherwise t|c, otherwise t|), so that a walker carries exactly the past that matters.

Edges have the attributes weight (the number of observations of the step, as in the paper; with the defaults of the analysis functions, the walks follow it) and probability (the weight over the out weight of its node). Nodes have the attributes first_order_node (the place, with the type of the input ids) and order (the length of the past of the node, 1 for first-order nodes). Without higher-order dependencies (or with max_order = 1), the result is the first-order network of the steps. Repeated consecutive nodes count as steps (self loops); remove them first if they are not moves.

The paper uses max_order = 5 and min_support between 5 and 10, to filter noise. The default here is min_support = 1, because dropping the rare steps of a past rescales the others, so a thinly observed past (say 6 observations: 5 to one node, 1 to another) looks certain of its next step and passes the threshold. On paths with no memory at all (walks on three random networks of 60 nodes, 2.4 million steps each), max_order = 5 gave 9,000 to 18,000 spurious higher-order nodes with min_support = 5 and 4 to 90 with 1 (none up to max_order = 4); on a tenth of the authors’ synthetic data, it gave 200 spurious nodes with 5 and none with 1 (the planted ones were found either way). More generally, the threshold is not a significance test: pasts observed few times compared with the number of their next steps can pass it by chance. A check: build the network of as many walks of the first-order network (max_order = 1, walking with weight) with the same settings, and compare the numbers of higher-order nodes.

All counts are computed at once by sorting (on device): 10 million steps take about 8 s on a CPU. The result is on device.

Parameters:

  • sequences – The paths: an iterable of sequences of node ids (e.g. lists); a pandas.DataFrame with one row per visit, a column node, an optional column step giving the order, and the other columns identifying the sequence (the output of random_walk() works as it is); or the path of a text file with one sequence per line (ids that all look like integers are read as integers; see labeled).

  • max_order – Longest past considered (1 gives the first-order network).

  • min_support – Fewest observations for a step to count (see above before raising it).

  • sep – Separator of the nodes in a file (None: any whitespace).

  • device – Device of the counts and of the result.

  • progress – Whether to show a progress bar (reading, each order, wiring; None: as set by set_progress(); see Progress bars).

  • labeled – Whether every line of the file starts with the id of its sequence, as in the authors’ data (ship port port ...): the id is skipped. Without it, the id would be read as the first node of the path, giving nodes such as 35|34.99388 (at 35, coming from 34, coming from “node” 99388, the trajectory id).

Returns:

Directed Network.

Raises:

ValueError – If max_order < 1, or no step is left.

Example:

graphoskop.memory_network(sequences, order=2, sep=None, labeled=False, device='cpu', progress=None)

Memory network of a set of sequences (Rosvall, Esquivel, Lancichinetti, West and Lambiotte, 2014): the network of a Markov chain of fixed order \(m\) on the paths. Its nodes (memory, or state, nodes) are the observed sequences of \(m\) steps, named as in higher_order_dependency_network(): with order = 2, k|j is being at k coming from j, the link \(\overrightarrow{jk}\) of the first-order network. Every observed \(m + 1\) steps (trigrams \(i \to j \to k\) for order = 2) add one to the weight of the edge from j|i to k|j, so the walker moves with

\[p(\overrightarrow{ij} \to \overrightarrow{jk}) = \frac{W(\overrightarrow{ij} \to \overrightarrow{jk})}{\sum_l W(\overrightarrow{ij} \to \overrightarrow{jl})}.\]

Unlike higher_order_dependency_network(), every past of length \(m\) is a node, whether it changes the next step or not: the model is simpler, and larger (one node per link of the first-order network for order = 2). As in the paper, a memory node never left in the data (the last steps of paths) moves as its physical node does in the data of one order less (k|j follows the observed steps out of k, to the nodes l|k), so that the walker does not get stuck. order = 1 gives the first-order network.

Edges have the attributes weight (observations) and probability; nodes have first_order_node (the physical node), order and count (the observations of the \(m\) steps, i.e. for order = 2 the weight \(W(j \to k)\) of the link of the first-order network). The analyses of the paper:

  • Flow and rankings. PageRank of the memory network, with the teleportation of the paper (to memory nodes in proportion to their count), summed over physical nodes: first_order_values(mem, pagerank(mem, weight = "weight", personalization = "count")).

Random walks and Laplacians

On a hypergraph, random_walk(), the Laplacian functions (Laplacians) and the node vector functions (Node vector analysis) use the random walk of Zhou, Huang and Schölkopf (2006): from a node, a hyperedge containing it with probability proportional to its weight (weight names a hyperedge attribute), then a node of that hyperedge, uniformly. They run on the network of that walk, hypergraph_walk_network(), whose Laplacian is the hypergraph Laplacian of Zhou et al.; random_walk() also reports the hyperedge of every step. The walks of Carletti et al. (2020) and of Chitra and Raphael (2019, edge-dependent vertex weights) are other networks of hypergraph_walk_network(), to pass to any function. On a simplicial complex, they use its 1-skeleton (see also Hodge Laplacians). Directed hypergraphs have random walks (from tails to heads) but no Laplacians yet.

import graphoskop as gsk

net = gsk.load_hypergraph({"m1": ["a", "b", "c"], "m2": ["b", "d"]})
gsk.laplacian(net)                                       # Zhou's hypergraph Laplacian
gsk.effective_resistance(net)
gsk.random_walk(net, "a", 5, seed = 0)                   # walk, step, node, hyperedge
g = gsk.hypergraph_walk_network(net, "carletti")
gsk.laplacian(g, weight = "weight")                      # Carletti et al.'s walk

With large hyperedges the walk network is large: a hyperedge of \(s\) nodes links \(s (s - 1) / 2\) pairs. Laplacian solvers, stationary distributions and sparse Fourier bases then work on the incidence matrix instead, with the same results in memory linear in the memberships; set_hypergraph_route() sets when.

graphoskop.hypergraph_walk_network(net, model='zhou', weight=None, vertex_weight=None, batch_size=16777216)

The network of the nodes of a hypergraph on which a random walk model moves: an edge from \(u\) to \(v\) weighs the probability of a step from \(u\) to \(v\), up to the factor that normalizes the steps from \(u\) (their sum \(d_u\), the strength of \(u\)). Every function of the library then applies to it; the Laplacian, random walk and node vector functions use model = "zhou" directly on a hypergraph (see Higher-order networks). \(w(e)\) is the hyperedge attribute weight (1 without it), \(|e|\) the size of \(e\):

  • "zhou" (Zhou, Huang and Schölkopf, 2006): from \(u\), a hyperedge \(e\) containing it with probability proportional to \(w(e)\), then a node of \(e\) uniformly, \(u\) included. Undirected, with weights \(A_{uv} = \sum_{e \ni u, v} w(e) / |e|\) (self loops included, \(d_u = \sum_{e \ni u} w(e)\)): the Laplacian \(D - A\) is the hypergraph Laplacian of Zhou et al., and the walk is reversible with stationary distribution proportional to \(d_u\).

  • "carletti" (Carletti, Battiston, Cencetti and Fanelli, 2020): steps to another node of a shared hyperedge, with \(A_{uv} = \sum_{e \ni u, v} w(e) (|e| - 1)\) for \(u \ne v\) and no self loops: larger hyperedges weigh more. Undirected and reversible; the paper has \(w(e) = 1\).

  • "edvw" (edge-dependent vertex weights, Chitra and Raphael, 2019): a hyperedge with probability proportional to \(w(e)\), then a node \(v\) of it with probability \(\gamma_e(v) / \delta(e)\), \(\gamma_e(v)\) the membership attribute vertex_weight and \(\delta(e) = \sum_{v \in e} \gamma_e(v)\). Directed (the walk is not reversible in general), with \(A_{uv} = \sum_{e \ni u, v} w(e) \gamma_e(v) / \delta(e)\), self loops included; its Laplacian in Chitra and Raphael is the Chung Laplacian (kind = "chung" with alpha = 0 in laplacian()).

The pairs of nodes sharing hyperedges are generated as in the bipartite projections, batch_size at a time: the number of edges grows with the squares of the hyperedge sizes. Nodes are those of net, in the same components and order, with the attributes that have values on some node (hyperedge attributes are dropped); the edge attribute "weight" holds \(A_{uv}\).

Hypergraphs: supported; simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – An undirected hypergraph.

  • model – "zhou", "carletti" or "edvw".

  • weight – Hyperedge attribute \(w(e)\), or None for 1.

  • vertex_weight – For "edvw", the membership attribute \(\gamma_e(v)\).

  • batch_size – Number of pairs of nodes sharing a hyperedge generated at once.

Returns:

New Network, undirected (directed for "edvw").

Raises:

  • ValueError – If net is not an undirected hypergraph, model is not valid, vertex_weight is missing for "edvw" (or given for another model), or weights are not positive and finite.

  • KeyError – If an attribute does not exist.

Example:

import graphoskop as gsk

gsk.laplacian(net)                                         # the Laplacian of the Zhou network
graphoskop.set_hypergraph_route(route='auto', ratio=1.0)

How the Laplacian solvers, stationary distributions and sparse Fourier bases of hypergraphs are computed. They are those of the random walk of Zhou et al. (see Random walks and Laplacians), whose network links every pair of nodes sharing a hyperedge: a hyperedge of \(s\) nodes gives \(s (s - 1) / 2\) pairs, so large hyperedges make it large (one of 10,000 nodes, 50 million pairs). The same products can be computed with the incidence matrix instead, \(L x = D x - H W B^{-1} H^T x\), in memory linear in the memberships, without building the network:

  • "auto" (default): with the incidence matrix when the walk network would have more than ratio times as many pairs as there are memberships (with the default ratio of 1, from a mean hyperedge size of about 3), with the walk network otherwise;

  • "incidence": always with the incidence matrix;

  • "walk_network": always with the walk network.

Results are the same either way, up to the tolerance of the iterative methods. The incidence matrix is used by laplacian_solver(), stationary_distribution(), generalized_euclidean() with a solver (sparse = True) and graph_fourier_basis() with a few modes (k) on large components (and so the Fourier transforms computing that basis). The other functions always build the walk network: dense ones (pseudoinverse, resistances, …) take memory quadratic in the nodes anyway, and some need its edges (e.g. earth_movers_distance()). Directed hypergraphs have no Laplacian.

Parameters:

  • route – "auto", "incidence" or "walk_network".

  • ratio – With "auto", the number of pairs per membership above which the incidence matrix is used.

Raises:

ValueError – If route is unknown or ratio negative.

Example:

import graphoskop as gsk

gsk.set_hypergraph_route()                            # back to the default

Tests

A hypergraph is uniform when all its hyperedges have the same size; a simplicial complex is pure when all its facets have the same dimension, and a pseudomanifold when, moreover, every face of dimension \(d - 1\) is shared by at most two \(d\)-simplices (incidence number 0 or 1) and the \(d\)-simplices are connected through these faces. Pseudomanifolds are the discrete manifolds of network geometry with flavor; being a manifold in the topological sense needs more (see is_pseudomanifold()).

import graphoskop as gsk

gsk.is_uniform(gsk.load_hypergraph([["a", "b", "c"], ["b", "c", "d"]]))      # True: 3-uniform
disk = gsk.load_simplicial_complex([["a", "b", "c"], ["b", "c", "d"]])
gsk.is_pure(disk), gsk.is_pseudomanifold(disk)                               # True, True
gsk.is_pseudomanifold(disk, boundary = False)                                # False: it has a boundary
graphoskop.is_pseudomanifold(net, boundary=True, batch_size=16777216)

Whether a simplicial complex is a \(d\)-dimensional pseudomanifold:

  1. it is pure of dimension \(d \ge 1\) (is_pure());

  2. every \((d - 1)\)-face is shared by at most two \(d\)-simplices: its incidence number (incidence_number()) is 0 or 1; with boundary = False, exactly two (incidence number 1 everywhere: a closed pseudomanifold, without boundary);

  3. it is strongly connected: any two \(d\)-simplices are joined by a chain of \(d\)-simplices, each sharing a \((d - 1)\)-face with the next, i.e. it has a single \((d - 1)\)-connected component (connected_components_count() with dimension = d - 1).

These are the discrete manifolds of network geometry with flavor (incidence numbers 0 or 1, flavor \(s = -1\); Bianconi and Rahmede, 2016). Every triangulated manifold is a pseudomanifold, but not conversely: a manifold also needs the link of every node (the faces opposite it in its simplices) to be a sphere, or a ball on the boundary. For \(d = 1\) the two coincide (paths and cycles); from \(d = 2\) they do not: a triangulated sphere with two of its nodes merged is a pseudomanifold whose merged node has two circles as link.

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

Raises:

Topological signals

Signals on the \(k\)-simplices of a complex (flows on its edges, values on its triangles) are simplex attributes, or vectors aligned with simplices(). The Hodge decomposition splits such a signal into a gradient part (differences of a potential on the \((k - 1)\)-simplices), a curl part (circulations around the \((k + 1)\)-simplices) and a harmonic part (around the holes of the complex), and the simplicial Fourier transform (Barbarossa and Sardellitti, 2020) expands it on the eigenvectors of the Hodge Laplacian, each of one of these three kinds. Signals on the nodes are analyzed in Node vector analysis; oscillators on simplices, in Synchronization.

import graphoskop as gsk
import pandas as pd

net = gsk.load_simplicial_complex([["a", "b", "c"], ["c", "d"], ["d", "e"], ["c", "e"]])
flows = pd.DataFrame({"u": ["a", "b", "a", "c", "d", "e"], "v": ["b", "c", "c", "d", "e", "c"], "flow": [1., 1., 0., 2., 2., 2.]})
net.set_simplex_attribute(flows, dimension = 1, oriented = True)
gradient, curl, harmonic = gsk.hodge_decomposition(net, "flow")
harmonic                                 # [0, 0, 0, 2, -2, 2]: the circulation c -> d -> e -> c
freq, U, kinds = basis = gsk.simplicial_fourier_basis(net, 1)
c = gsk.simplicial_fourier_transform(net, "flow", basis = basis)
smooth = gsk.inverse_simplicial_fourier_transform(net, c * (freq < 2), basis = basis)
graphoskop.hodge_decomposition(net, signal, dimension=None, component=0, tol=1e-10, max_iter=None)

Hodge decomposition of a signal on the \(k\)-simplices of a simplicial complex (a flow on its edges for \(k = 1\)) into three orthogonal parts (Lim, 2020; Barbarossa and Sardellitti, 2020), \(x = B_k^T a + B_{k + 1} b + h\):

  • gradient \(B_k^T a\): differences of a potential \(a\) on the \((k - 1)\)-simplices (for edges, a flow from high to low node potential), free of curl;

  • curl \(B_{k + 1} b\): circulations around the \((k + 1)\)-simplices (for edges, flows around filled triangles), free of divergence;

  • harmonic \(h\): the rest, free of both (\(B_k h = 0\), \(B_{k + 1}^T h = 0\), \(L_k h = 0\)), flowing around the holes of the complex; it is zero if the complex has no \(k\)-dimensional hole (betti_numbers()).

Signals are in the reference orientation of the simplices (see set_simplex_attribute()), as the boundary matrices (boundary_matrix()). For \(k = 0\) (a node signal), the gradient part is zero and the harmonic part is the mean over the component. The two projections solve \(B_k B_k^T a = B_k x\) and \(B_{k + 1}^T B_{k + 1} b = B_{k + 1}^T x\) by conjugate gradients on the sparse boundary matrices, in double precision, on the device of the network.

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

Parameters:

  • net – A simplicial complex.

  • signal – Simplex attribute (name, see set_simplex_attribute(); or a node attribute for \(k = 0\)), list of them, or a vector (one value per \(k\)-simplex, in the order of simplices()) or matrix (one signal per column).

  • dimension – Dimension \(k\) of the simplices; None to take it from the attributes.

  • component – Index of the component (0 is the largest).

  • tol – Relative residual at which conjugate gradients stop.

  • max_iter – Largest number of conjugate gradient iterations, or None for 10 times the number of simplices of the system.

Returns:

(gradient, curl, harmonic): three tensors of the shape of the signal, summing to it.

Raises:

ValueError – If net is not a simplicial complex, the dimension is missing, the signal has the wrong length or missing values, or conjugate gradients do not converge.

Example:

import graphoskop as gsk
import pandas as pd

net = gsk.load_simplicial_complex([["a", "b", "c"], ["c", "d"], ["d", "e"], ["c", "e"]])
flows = pd.DataFrame({"u": ["a", "b", "a", "c", "d", "e"], "v": ["b", "c", "c", "d", "e", "c"], "flow": [1., 1., 0., 2., 2., 2.]})
net.set_simplex_attribute(flows, dimension = 1, oriented = True)
gradient, curl, harmonic = gsk.hodge_decomposition(net, "flow")
(harmonic ** 2).sum() / net.get_simplex_attribute("flow").double().pow(2).sum()   # share around the hole c, d, e

graphoskop.simplicial_fourier_basis(net, dimension, component=0)

Fourier basis of the signals on the \(k\)-simplices of a simplicial complex (Barbarossa and Sardellitti, 2020): the eigenvalues (frequencies) and eigenvectors (modes) of the Hodge Laplacian \(L_k = B_k^T B_k + B_{k + 1} B_{k + 1}^T\) (hodge_laplacian()), each mode of one of the three kinds of hodge_decomposition(): "harmonic" (frequency 0, one per \(k\)-dimensional hole), "gradient" (eigenvectors of \(B_k^T B_k\)) or "curl" (eigenvectors of \(B_{k + 1} B_{k + 1}^T\)). For \(k = 0\) this is the graph Fourier basis of the 1-skeleton (graph_fourier_basis()), with curl modes for the nonzero frequencies. Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

Parameters:

  • net – A simplicial complex.

  • dimension – Dimension \(k\) of the simplices.

  • component – Index of the component (0 is the largest).

Returns:

(frequencies, modes, kinds): vector of length \(n_k\), \(n_k\) by \(n_k\) matrix (one mode per column), and NumPy array of the kind of each mode.

Raises:

ValueError – If net is not a simplicial complex or dimension is negative.
