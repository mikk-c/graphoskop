Graph neural networks

Graph neural networks: node attributes predicted from the other node attributes and the network, with the layers of PyTorch Geometric. Four models share the same parameters and output: gcn() (graph convolutions), graphsage() (own features kept apart from the mean of the neighbors’), gat() and gatv2() (attention weighted averages of the neighbors). gae() and vgae(), graph autoencoders, learn node vectors without a target, from the node attributes and the edges, by reconstructing the edges. node2vec(), struc2vec(), metapath2vec(), laplacian_eigenmaps() and locally_linear_embedding() are shallow embeddings instead: unsupervised, they give one vector per node from the structure alone, with no target and no features, learned from random walks (similar vectors for nearby nodes, for nodes with similar roles with struc2vec(), or along chains of node types with metapath2vec()) or computed as eigenvectors. diffpool() gives one vector per graph (per component), pooling the nodes of each graph into clusters, with or without a graph attribute to predict. On hypergraphs and simplicial complexes, hgnn() predicts node attributes through the hyperedges (or facets), and scnn() predicts attributes of the edges, triangles… of a complex, with the same parameters and output.

A model is a stack of graph convolution layers, given by the number of output channels of each layer: [32, 16, 2] is three layers, from the input features to 32, then 16, then 2 channels, the last one being the output (one channel per class, or one for a number). An activation (or none) follows each layer, and dropout precedes each layer. The node attribute to predict is the target; the features are all the other numeric node attributes (missing values replaced by the mean, then standardized) and, optionally, the qualitative ones as dummy variables (one 0 / 1 column per value; a node with several values gets several ones). A network without features gets a constant feature, so that the model learns from the structure alone.

The feature matrix is built directly on the device of the network. When it would be large (more than 67 million entries) and mostly zeros (fewer than 10% nonzero), as with the many attributes of a long node table (one per label, genre, year…) or the dummies of an attribute with a value per node, it is kept sparse: its memory is that of its nonzero values, and the layers multiply it as a sparse matrix. Sparse numeric features are standardized by scaling only (unit variance, mean not removed), so that zeros stay zeros.

The nodes with a known target are split at random into a training set, whose loss trains the model, and a validation set, which only measures how well the model generalizes; the nodes without a target are predicted too. The whole network is one graph: all components, on its device (GPU if there).

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")       # node attributes: age, income, city
out = gsk.gcn(net, "city", [32, 16, 4], qualitative = True, split = (0.6, 0.2), seed = 1)
out["scores"]                                          # accuracy and macro F1, training and validation
out["predictions"].query("set == 'unlabeled'")         # predicted city of the nodes without one
out["history"].plot(x = "epoch")                       # training and validation loss
reg = gsk.gcn(net, "income", [16, 1], activations = ["tanh", None], epochs = 500, learning_rate = 0.005)

Autoencoders

Graph autoencoders learn node vectors without a target: an encoder of GCN layers gives every node a vector from the node attributes and the edges, trained so that the dot products of the vectors reconstruct the edges. Unlike the shallow embeddings below, they use the node attributes, and the trained encoder (out["model"]) can embed new nodes from their attributes.

train, validation = gsk.link_prediction_split(net, seed = 1)
out = gsk.vgae(train, seed = 1, attribute = "z")          # vectors stored as z_0 ... z_15
scored = gsk.embedding_lp(train, validation, [f"z_{j}" for j in range(16)])
graphoskop.gae(net, channels=(32, 16), features=None, qualitative=False, standardize=True, weight=None, epochs=200, optimizer='adam', learning_rate=0.01, weight_decay=0.0, dropout=0.0, seed=None, attribute=None, progress=None)

Graph autoencoder (Kipf and Welling, 2016): node vectors learned by a graph neural network (the encoder) so that the edges of the network can be reconstructed from them (the decoder), from the node attributes and the edges, without any target.

The encoder is a stack of GCN layers (as in gcn(), with the normalized adjacency computed once as a sparse matrix), with channels giving the output size of each layer, the last one being the size of the node vectors ([32, 16] as in the paper), ReLU between them and dropout before each. The features are the node attributes, prepared as in gcn(); without any, the features are the one-hot node ids (the identity matrix, sparse), as in the paper. The decoder is the inner product: the probability of an edge between \(u\) and \(v\) is \(\sigma(z_u^T z_v)\), and the loss is the binary cross entropy of all the edges (self loops excluded) against as many random pairs of nodes, drawn anew at every epoch, with PyTorch Geometric’s GAE. Training is unsupervised and uses all the nodes and edges at every epoch: to test the vectors on link prediction, train on the training network of link_prediction_split() and score the pairs with the dot product of their vectors, or with embedding_lp().

Parameters:

  • net – A Network.

  • channels – Output channels of each layer, the last one being the size of the node vectors.

  • features – Names of the node attributes to use as features (None: all).

  • qualitative – Whether to include the qualitative node attributes as dummy variables.

  • standardize – Whether to standardize the numeric features.

  • weight – Name of a numeric edge attribute weighting the edges in the GCN layers, or None.

  • epochs – Number of training epochs (full passes over the network).

  • optimizer – "adam", "adamw", "sgd", "rmsprop", or a torch.optim.Optimizer class.

  • learning_rate – Learning rate.

  • weight_decay – Weight decay (L2 penalty).

  • dropout – Dropout probability before each layer.

  • attribute – Prefix of numeric node attributes <attribute>_0, <attribute>_1, … where to store the vectors, or None to only return them.

  • progress – Whether to show a progress bar over the epochs (None: as set by set_progress(); see Progress bars).

Raises:

Variational graph autoencoder (Kipf and Welling, 2016): as gae(), but the encoder gives a distribution of every node vector, a Gaussian with a mean and a standard deviation per dimension (the last layer is two GCN layers, one for the means and one for the log standard deviations, after the shared ones), and the decoder reconstructs the edges from vectors drawn from them. Training is unsupervised and uses all the nodes and edges at every epoch: to test the vectors on link prediction, train on the training network of link_prediction_split() and score the pairs with the dot product of their vectors, or with embedding_lp().

Graph embeddings

A network whose components are the graphs of a dataset (molecules, ego networks…) gets one vector per graph with diffpool(), trained to predict a graph attribute or, without one, unsupervised.

molecules = gsk.load_network("bonds.tsv", "atoms.tsv")    # one component per molecule
out = gsk.diffpool(molecules, "toxic", seed = 1)           # a node attribute, one value per molecule
out["scores"], out["predictions"]                          # as for the node models below
free = gsk.diffpool(molecules, seed = 1)["embeddings"]     # unsupervised: one row per molecule
graphoskop.diffpool(net, target=None, clusters=(0.25,), channels=64, features=None, qualitative=False, standardize=True, task=None, weight=None, split=(0.8, 0.2), epochs=100, optimizer='adam', learning_rate=0.01, weight_decay=0.0, loss=None, seed=None, progress=None)

Graph embeddings by differentiable pooling (DiffPool; Ying, You, Morris, Ren, Hamilton and Leskovec, 2018): one vector per graph, where every component of net is a graph (a network whose components are the graphs of a dataset, as in transactional_graph_mining()), learned from the node attributes and the edges.

At every pooling level, two graph neural networks run on each graph: one gives every node a vector \(Z\), the other a soft assignment \(S\) of every node to the clusters of the level (a softmax over them). The graph is then replaced by its clusters: their vectors are \(S^T Z\) and their weighted adjacency \(S^T A S\), so the next level runs on a smaller, coarser graph. After the last level, a last network embeds the clusters, and the mean of their vectors is the graph embedding. Every network has two GraphSAGE layers (mean of the neighbors, as in the paper) with ReLU activations. clusters gives the number of clusters of each level: a fraction of the size of the level before (of the largest graph, for the first level), or a count; the default is one level with 25% of the nodes of the largest graph, as in the paper. Every graph gets the same number of clusters, whatever its size.

The networks are trained together, by gradient descent over all the graphs at once, with two losses of the paper that make clusters meaningful: the link loss, \(\|A - S S^T\|_F^2\) (nodes joined by an edge should share their clusters), divided by the number of entries of \(A\) and averaged over the graphs and levels, and the entropy of the assignments, averaged over the nodes and levels (each node should belong mostly to one cluster). Then:

  • with a target, a graph attribute to predict, the graph embedding goes through a linear layer to predict it, and its loss (cross entropy for classification, mean squared error for regression, or loss) is added: the graphs with a known target are split into a training set, whose loss trains the networks, and a validation set, as in gcn();

  • without a target, the cluster losses alone would only train the assignments, not the node vectors, so the node vectors of the first level (before their last activation, so that dot products can be negative) are also trained to reconstruct the edges, as in graph autoencoders (Kipf and Welling, 2016): the logistic loss of the dot products of the two ends of every edge, against those of as many random pairs of nodes of the same graph.

The features are the node attributes, prepared as in gcn() (numeric ones, qualitative ones as dummies with qualitative, sparse when large). Without any, the feature is the (log, standardized) in-degree: the mean of constant features over the neighbors would be constant, and the networks could not see the structure of the graphs. The first level runs on the sparse network (no dense matrix of the nodes of a graph is built): its memory grows with the number of nodes times the number of clusters, plus the number of graphs times the square of the number of clusters (the pooled graphs, dense).

DiffPool is meant for datasets of many small graphs (molecules, proteins, ego networks: tens to hundreds of nodes each), to compare or classify graphs. It runs on a single large graph too (6,000 nodes in about 1.4 s per epoch, 1 GB), but gives a single vector, meaningful only next to the vectors of other graphs computed in the same call; to embed the nodes of one network, use node2vec(), laplacian_eigenmaps() or locally_linear_embedding(). Since the default number of clusters is a share of the largest graph, a dataset with one large component gives every graph that many clusters, each pooled into a dense matrix of clusters by clusters: with many graphs (isolated nodes are graphs too) this needs a lot of memory, so diffpool refuses more than \(2^{28}\) entries in all (graphs times clusters squared), with a ValueError that suggests a count of clusters to give in clusters instead. A graph label given as the name of a node attribute must have one value per component (missing on some nodes allowed). With weight, edges are weighted in the neighborhood means and in \(A\).

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network, one graph per component.

  • target – The graph attribute to predict: the name of a node attribute with one value per component, or one value per component (list, array or pandas.Series indexed by component), missing values allowed; or None for unsupervised embeddings.

  • clusters – Number of clusters of each pooling level: fractions of the size of the level before, or counts.

  • channels – Size of every node vector and of the graph embedding.

  • features – Names of the node attributes to use as features (None: all but the target).

  • qualitative – Whether to include the qualitative node attributes as dummy variables.

  • standardize – Whether to standardize the numeric features.

  • task – "classification", "regression" or None (from the type of the target).

  • weight – Name of a numeric edge attribute weighting the edges, or None.

  • split – Fractions of the graphs with a target in the training and validation sets.

  • epochs – Number of training epochs (full passes over all the graphs).

  • optimizer – "adam", "adamw", "sgd", "rmsprop", or a torch.optim.Optimizer class.

  • learning_rate – Learning rate.

  • weight_decay – Weight decay (L2 penalty).

  • loss – Loss of the target: as in gcn(), or None for the default of the task.

  • seed – Seed of the split, the initial weights and the random pairs, or None.

  • progress – Whether to show a progress bar over the epochs (None: as set by set_progress(); see Progress bars).

Returns:

Dictionary with "embeddings" (pandas.DataFrame, one row per graph, indexed by component, one column per channel), "assignments" (one row per node: node id, graph and its most likely first level cluster), "history" (losses at each epoch), "model" (the trained torch.nn.Module) and "features"; with a target also "scores", "predictions" (one row per graph: graph, set, target, prediction and the probability p_<class> of each class) and "task", as in gcn().

Raises:

ValueError – If a target given by name has several values in a component, the target does not have one value per component, or a parameter is not valid.

Example:

out["scores"]                                               # accuracy and F1, training and validation
out["embeddings"]                                           # one vector per molecule

Higher-order networks

Hypergraphs and simplicial complexes (see Higher-order networks) have two models, with the parameters and results of the models below. hgnn() predicts a node attribute: its layers (the hypergraph convolution of HypergraphConv in PyTorch Geometric) pass features from the nodes to their hyperedges and back, so that a group of any size counts once, without the many pairs of the clique expansion; on a simplicial complex, the facets are the hyperedges. scnn() predicts a simplex attribute of a simplicial complex, a value or a class of every edge (or triangle…), from the other attributes of the simplices of that dimension: its layers mix every simplex with those sharing a face with it and, separately, those sharing a coface with it, through the lower and upper Hodge Laplacians (see Hodge Laplacians). The other models refuse higher-order networks: pass them clique_expansion() for the network of co-members.

import graphoskop as gsk

hg = gsk.load_hypergraph("authorships.tsv", "authors.tsv")      # papers and their authors
out = gsk.hgnn(hg, "field", [32, 5], seed = 1)                  # a node attribute
out = gsk.hgnn(hg, "field", [32, 5], weight = "citations")      # a hyperedge attribute

sc = gsk.load_simplicial_complex("cliques.tsv")
sc.set_simplex_attribute(edge_table, dimension = 1)              # node_0, node_1, kind, weight
out = gsk.scnn(sc, "kind", [32, 3], order = 2, seed = 1)         # a class of every edge
out["predictions"]                                               # one row per edge, Simplex ids

On a planted hypergraph (400 nodes in 4 groups, 600 hyperedges of 3 to 6 nodes, 85% inside a group, one noisy group feature), hgnn() reaches a validation accuracy of 0.84 (0.45 from the features alone), and gcn() on the clique expansion 0.95: the hypergraph layer keeps more of every node’s own (noisy) features, which here smooths too little; on 100,000 nodes and 100,000 hyperedges, 50 epochs take 11 s on two CPU threads. With a constant feature only, scnn() tells the edges in a filled triangle from the others (accuracy 1.0), which needs the upper neighbors; on 72,849 edges and 42,850 triangles, 50 epochs take 10 s.

Hypergraph neural network predicting a node attribute of a hypergraph or a simplicial complex, with the hypergraph convolution of Feng et al. (2019) and Bai, Zhang and Torr (2021), the HypergraphConv layer of PyTorch Geometric. Each layer averages the features of the nodes of every hyperedge, then gives every node the weighted average of its hyperedges and transforms it linearly, \(D^{-1} H W B^{-1} H^T X \Theta\), with \(H\) the incidence matrix, \(W\) the hyperedge weights, \(B\) the hyperedge sizes and \(D = H W 1\). A group counts once whatever its size, where in the clique expansion a large group adds many edges; a node keeps a large share of its own features (through the means of its hyperedges), so the layer smooths less than gcn() on the clique expansion. On a simplicial complex the hyperedges are its facets: its faces add no group beyond them. A node in no hyperedge gets one holding it alone, so that it keeps its own features. Directions of directed hypergraphs are ignored.

Each layer is two products with sparse matrices computed once, as in gcn(), rather than HypergraphConv itself, whose hyperedge weights enter the node degrees only, not the averages (same layer and initialization otherwise; without weights, the outputs are the same). Its attention variant, which scores nodes against hyperedge features, is left out.

With weight, a numeric hyperedge (or facet) attribute weights the hyperedges in the average of every node; the hyperedges added for nodes in none weigh 1. Features, target, split, training and the returned dictionary are those of gcn(): features and target are node attributes (of the nodes only, not of the hyperedges or facets).

Hypergraphs and simplicial complexes: supported (see Higher-order networks).

Simplicial convolutional neural network (Yang, Isufi and Leus, 2022; after Ebli, Defferrard and Spreemann, 2020) predicting a simplex attribute of a simplicial complex, such as a value or a class of its edges or triangles (see set_simplex_attribute()), from the other simplex attributes of the same dimension. Each layer combines, for every \(k\)-simplex, its own features with those of the simplices sharing a face with it (lower neighbors, through the lower Laplacian \(L_d = B_k^T B_k\)) and those sharing a coface with it (upper neighbors, through \(L_u = B_{k + 1} B_{k + 1}^T\)), each with its own weights: \(X W_0 + \sum_{p = 1}^K (L_d^p X W_{d, p} + L_u^p X W_{u, p})\). With order \(K\), it reaches up to \(K\) steps away along faces and cofaces. Two edges are lower neighbors when they share a node, upper neighbors when they share a filled triangle: the layer tells the two apart, which a graph network on the line graph cannot. PyTorch Geometric has no such layer: it is implemented here, as sparse matrix products.

With oriented, the attributes are oriented signals (flows: a value on the edge from u to v is minus the value from v to u, in the reference orientation of set_simplex_attribute()), and the Laplacians keep the signs of the boundary matrices, so that the layers see how flows add up or cancel around nodes and triangles. Without it (the default), the attributes are values of the simplices whatever their orientation (a weight, a type), and the Laplacians are taken in absolute value, so that the arbitrary reference orientation does not matter. Each Laplacian is divided by its largest absolute row sum.

Features are the other numeric simplex attributes of the dimension of the target (missing values replaced by the mean, then standardized) and, with qualitative, the qualitative ones as dummies; without any, a constant feature. All components are used. Split, training and the returned dictionary are those of gcn(), with simplices instead of nodes: the predictions have a simplex column (Simplex ids) instead of node.

Simplicial complexes: supported; hypergraphs: not supported (see Higher-order networks).

graphoskop.laplacian_eigenmaps(net, dimensions=16, weight=None, attribute=None)

Laplacian eigenmaps (Belkin and Niyogi, 2003): node vectors that keep neighbors close, the dimensions smallest non trivial solutions of \(L y = \lambda D y\), with \(L = D - A\) the Laplacian and \(D\) the degree matrix. They minimize \(\sum_{uv} A_{uv} \|y_u - y_v\|^2\) under \(y^T D y = 1\) and orthogonality to the constant vector: nodes joined by many or heavy edges get similar vectors, and the first dimension is the Fiedler vector of the normalized Laplacian, which splits the network into its two most separated parts. Unlike node2vec(), there is no training and nothing random: the vectors are eigenvectors.

Each component is embedded on its own (its trivial solution is constant on it), so vectors of different components are not comparable; a component with fewer than dimensions + 1 nodes gets zeros in the dimensions it does not have, isolated nodes get zeros. Directed networks are treated as undirected (\(A + A^T\)), self loops are ignored, parallel edges are summed. Components of at most 2,000 nodes are solved exactly with a dense eigendecomposition, larger ones with the Lanczos method (ARPACK, through SciPy, on the CPU) on the normalized adjacency \(D^{-1/2} A D^{-1/2}\), whose largest eigenvalues are the smallest of the normalized Laplacian. Vectors are ordered by eigenvalue, the smoothest first, and the sign of each makes its largest entry positive. The vectors are normalized as the eigenvectors they are, so their entries shrink with the size of the network (about \(1 / \sqrt{n}\)): standardize them before methods sensitive to scale, such as penalized regressions (embedding_lp() and the models above standardize their inputs already).

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Every epoch, walks_per_node walks of walk_length nodes start from every node. Walks are of second order: from v, reached from t, the next node is a neighbor x of v, with probability proportional to the weight of the edge times 1 / p if x is t (going back), 1 if x is also a neighbor of t, 1 / q otherwise (going away). A low q explores far from the start (as a depth first search: similar vectors for nodes of the same community); a high q stays around it (as a breadth first search: similar vectors for nodes with similar roles, e.g. hubs); a high p avoids going back. With p = q = 1 walks are plain random walks: this is DeepWalk (Perozzi, Al-Rfou and Skiena, 2014). In directed networks walks follow the edges, and stop at a node without out edges.

The vectors are trained on the device of the network, with the objective of PyTorch Geometric’s Node2Vec (skip-gram with negative sampling): in every stretch of context_size consecutive nodes of a walk, the first node should have a large dot product with each of the others (positive pairs), and a small one with negative_samples random nodes in their place (negative pairs); the loss is the logistic loss of all pairs, minimized with sparse Adam over batches of batch_size starting nodes. The dot products of each walk are computed all at once, and walks are drawn on the device too (by rejection, so exactly with the probabilities above). The initial vectors are small (standard deviation \(0.1 / \sqrt{dimensions}\), as in word2vec): with the larger ones of PyTorch Geometric (standard deviation 1), dot products start saturated and training needs tens of epochs, while one epoch is usually enough here. Isolated nodes keep their random initial vectors. In multilayer networks walks cross layers through the interlayer edges, and every copy of an entity gets its own vector.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Parameters:

  • net – A Network.

  • dimensions – Number of numbers of each vector.

  • walk_length – Number of nodes of each walk, the start included.

  • context_size – Number of consecutive nodes of a walk in each positive example (at most walk_length).

  • walks_per_node – Number of walks from every node, every epoch.

  • p – Return parameter: going back is 1 / p times as likely.

  • q – In-out parameter: going away from the previous node is 1 / q times as likely.

  • negative_samples – Number of negative examples per positive one.

  • weight – Name of a numeric edge attribute weighting the edges, or None.

  • epochs – Number of passes over all the nodes, each with new walks.

  • batch_size – Number of starting nodes per training step.

  • learning_rate – Learning rate.

  • seed – Seed of the walks, the negative examples and the initial vectors, or None.

  • attribute – Prefix of numeric node attributes <attribute>_0, <attribute>_1, … where to store the vectors (e.g. as features of gcn()), or None to only return them.

  • progress – Whether to show a progress bar over the training steps (None: as set by set_progress(); see Progress bars).

Returns:

pandas.DataFrame with one row per node, indexed by node id ((entity, layer) in multilayer networks), in the network wide node order, and one column per dimension.

Raises:

ValueError – If a size or parameter is not positive, context_size is larger than walk_length, or weights are negative or missing.

struc2vec node embeddings (Ribeiro, Saverese and Figueiredo, 2017): vectors that are similar for nodes with similar structural roles (hubs, bridges, peripheral nodes…), wherever they are in the network, even in different components. node2vec() instead gives similar vectors to nodes that are close to each other.

The structural distance of two nodes \(u\) and \(v\) compares their neighborhoods ring by ring: \(R_k(u)\) is the set of nodes at distance exactly \(k\) from \(u\), and \(f_k(u, v) = f_{k - 1}(u, v) + g(s(R_k(u)), s(R_k(v)))\), where \(s\) is the sorted degree sequence of a ring and \(g\) the dynamic time warping distance of two sequences, matching degrees \(a\) and \(b\) at cost \((\max(a, b) + 0.5) / (\min(a, b) + 0.5) - 1\) (the 0.5 lets isolated nodes, of degree 0, be compared). Layer \(k\) of a multilayer graph joins nodes with weight \(e^{-f_k(u, v)}\), for \(k = 0\) (the degrees of the two nodes) to layers; a node is joined to itself in the layers above and below, with weight \(\log(\Gamma_k(u) + e)\) up, where \(\Gamma_k(u)\) is the number of its edges in layer \(k\) heavier than the mean edge of the layer, and 1 down. Random walks start at layer 0 of every node; at every step a walk moves within its layer with probability stay, to a neighbor drawn by edge weight, or else changes layer, up or down by these weights. The vectors are then trained on the walks as in node2vec() (skip-gram with negative sampling).

As in the paper, three approximations make this feasible on large networks: degree sequences are compressed into distinct degrees with their counts (a match then costs the cost above times the larger count); only layers layers are used (rings up to that distance); and each node is compared only with the candidates nodes closest to it in the order of the degrees (half with lower or equal degree, half with higher or equal), \(2 \lceil \log_2 n \rceil\) by default, or with all the other nodes when the network has at most 2,000 nodes. Rings come from breadth first searches from every node, and distances from dynamic time warping of every pair of candidates, both compiled and in parallel on the CPU threads; walks are drawn on the CPU too, and the vectors are trained on the device of the network. Training takes most of the time, and grows with walk_length: the default, 80 as in the paper, gives slightly better vectors than 20 (the default of node2vec()), which is about 4 times faster.

The network is used as undirected and simple (directions, weights, self loops and parallel edges ignored): roles here are made of degrees. Rings of a node never leave its component, but nodes of different components are compared like any others.

Hypergraphs and simplicial complexes: not supported (see Higher-order networks).

Graph autoencoders, with the defaults ([32, 16], 200 epochs), on two CPU threads.
