Link prediction

Link prediction: scoring the node pairs of a network by how likely they are to be connected.

Scoring every pair is unfeasible on large networks, since their number grows quadratically with the number of nodes. A link prediction is therefore tested on a sample of pairs: link_prediction_split() hides some edges of a network, the positives, and draws as many pairs of unconnected nodes, the negatives (or a multiple of them). It returns the training network, without the hidden edges, and the validation set, a table of the positive and negative pairs. A score, such as preferential_attachment_lp(), is then computed only for the pairs of the validation set, from the training network, and link_prediction_evaluation() tells how well it separates the positives from the negatives (area under the ROC and precision-recall curves, and the curves themselves).

Scores:

  • preferential_attachment_lp(): the product of the degrees of the two nodes;

  • common neighbors: the more neighbors the two nodes share, the higher the score, counted as

    • common_neighbors_lp(): the number of neighbors the two nodes share;

    • common_neighbors_jaccard_lp(): the common neighbors as a fraction of the neighbors of either node;

    • adamic_adar_lp(): each common neighbor weighted by one over the log of its degree;

    • resource_allocation_lp(): each common neighbor weighted by one over its degree;

    • car_index_lp(): the common neighbors times the links among them;

    • mutual_information_index_lp(): the information the common neighbors carry about an edge;

  • random walks: local_random_walk_lp(), the probability that a short random walk goes from one node to the other, and simrank_lp(), the chance that two walks started at the two nodes meet soon;

  • vertex_similarity_lp(): the paths of all lengths between the two nodes, relative to the number expected from their degrees;

  • models fitted to the network by Markov chain Monte Carlo, which learn any pattern of connection, assortative or not: hierarchical_random_graph_lp(), the edge probability of the pair in hierarchical random graphs, and block_model_reliability_lp(), in stochastic block models.

ensemble_link_prediction() aggregates the rankings of several scores into one (Borda count or Kendall tau). In signed networks, link_prediction_sign_evaluation() tests how well social balance and social status predict the signs of the hidden edges.

All take the network to compute the scores in, the pairs, and the name of the score column; the scores that have a weighted version take an optional edge attribute as weight, and the others their own parameters. Degree and common neighbor scores are computed on the device of the network, as is vertex similarity; local random walks use SciPy, and SimRank and the fitted models run on the CPU threads, compiled with Numba (Markov chains are sequential). All scores are float64, so products and sums of degrees are exact up to \(2^{53}\), and never overflow; scores only matter through their order, so they are not normalized.

Pairs are always given by node ids, never by internal ids, since removing edges can split a component and change the internal ids. Node attributes can therefore be joined to the validation set by id, e.g. with pandas.DataFrame.merge().

Self loops are neither hidden nor drawn as negatives. In undirected networks a pair is unordered, in directed networks a pair (u, v) stands for an edge from u to v. In bipartite networks, only pairs of nodes of different types are drawn, and in undirected bipartite networks the source is the node of type 0. Multilayer networks are not supported yet.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
train, validation = gsk.link_prediction_split(net, fraction = 0.1, negatives = 1, seed = 1)
validation = gsk.preferential_attachment_lp(train, validation)
gsk.link_prediction_evaluation(validation)              # {"auc": ..., "average_precision": ...}

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
train, validation = gsk.link_prediction_split(net, fraction = 0.1, negatives = 1, seed = 1)
validation = gsk.preferential_attachment_lp(train, validation)            # adds a "score" column
gsk.link_prediction_evaluation(validation)                 # {"auc": ..., "average_precision": ...}

# several scores side by side, one column each
for f in (gsk.common_neighbors_lp, gsk.common_neighbors_jaccard_lp, gsk.adamic_adar_lp, gsk.resource_allocation_lp,
          gsk.car_index_lp, gsk.mutual_information_index_lp, gsk.local_random_walk_lp, gsk.vertex_similarity_lp):
   validation = f(train, validation, name = f.__name__)
validation = gsk.simrank_lp(train, validation, walks = 1000, name = "simrank_lp", seed = 1)
validation = gsk.hierarchical_random_graph_lp(train, validation, name = "hrg", seed = 1)
validation = gsk.block_model_reliability_lp(train, validation, name = "sbm", seed = 1)
result = gsk.link_prediction_evaluation(validation, score = "hrg", curves = True)
ax = result["roc_curve"].plot(x = "fpr", y = "tpr", label = "HRG")
result["precision_recall_curve"].plot(x = "recall", y = "precision")

# ensembles: aggregate the rankings of several scores
validation = gsk.ensemble_link_prediction(train, validation, ["common_neighbors_lp", "local_random_walk_lp"], name = "borda")
validation = gsk.ensemble_link_prediction(None, validation, aggregation = "kendall",
                                          columns = ["common_neighbors_lp", "local_random_walk_lp", "sbm"], name = "kemeny")

# signed networks: can social balance and social status predict the signs of the hidden edges?
signed = gsk.load_network("signed_edges.tsv", directed = True)   # edge attribute "sign"
s_train, s_validation = gsk.link_prediction_split(signed, seed = 1)   # s_validation gets a "sign" column
gsk.link_prediction_sign_evaluation(s_train, s_validation)         # balance_accuracy, status_accuracy, ...

# weighted scores, one pair or a list of pairs
validation = gsk.resource_allocation_lp(train, validation, weight = "weight", name = "ra_weighted")
validation = gsk.local_random_walk_lp(train, validation, steps = 4, superposed = True, name = "srw")
gsk.common_neighbors_lp(net, ("alice", "bob"))
gsk.common_neighbors_jaccard_lp(net, [("alice", "bob"), ("bob", "carol")])

Ensembles

Scores that capture different patterns can be combined by aggregating their rankings, with the Borda count or a locally Kemeny optimal ranking (Kendall tau). On the benchmark networks below, an ensemble of common neighbors, resource allocation, CAR, local random walks and preferential attachment scores between its members (AUC 0.75 with Borda and 0.72 with Kendall on the karate club, where local random walks alone reach 0.89; 0.90 on the communities, where the best member reaches 0.92): aggregation helps when the scores are good and make different mistakes, and is dragged down by weak ones.

graphoskop.ensemble_link_prediction(net, pairs, methods=None, aggregation='borda', columns=None, name='score')

Ensemble of link prediction scores: several scores rank the pairs, and their rankings are aggregated into one.

The scores are either computed, by giving methods, a list of score functions of this module (e.g. common_neighbors_lp()), their names (e.g. "adamic_adar_lp"), or pairs (function, keyword arguments) (e.g. (gsk.simrank_lp, {"seed": 1})), each run on net and stored in a column named after the function (with _2, _3… for repeated functions); or taken from pairs, a pandas.DataFrame with the endpoints in its first two columns (as source and target) and scores in others: the columns named in columns, or all the other numeric columns except label. net is then not needed (None). Both can be combined: computed scores and the given columns.

Only the order of each score matters, so scores on different scales combine. Each score ranks the pairs from the lowest to the highest, ties sharing their average rank, NaN ranked lowest.

  • aggregation = "borda": the Borda count, the sum over the scores of the number of pairs ranked below the pair (ties counting one half).

  • aggregation = "kendall": the ranking that minimizes the total Kendall tau distance to the rankings of the scores (the number of pairs of pairs they order differently), the Kemeny ranking. Finding it is NP-hard, so it is approximated by local Kemenization (Dwork, Kumar, Naor and Sivakumar, 2001): from the Borda ranking, each pair moves up past the pairs above it as long as a strict majority of the scores ranks it higher. The result is locally Kemeny optimal (no two consecutive pairs are ordered against the majority), and every move brings it closer to the scores, so it is at least as close as the Borda order it starts from (Borda ties broken by the order of the pairs). Unlike the Borda count it leaves no ties, except between pairs that all the scores rank the same, so where the scores disagree evenly it can be farther from them than the Borda count with its ties. The score is the position from the bottom (the best pair scores the number of pairs), averaged over pairs that all the scores rank the same. Compiled with Numba; the time grows with the number of moves, small when the scores mostly agree.

Parameters:

  • net – A Network to compute methods in, or None.

  • pairs – Pairs, as in preferential_attachment_lp(); a pandas.DataFrame of scores without methods.

  • methods – Scores to compute, or None.

  • aggregation – "borda" or "kendall".

  • columns – Names of score columns of pairs to aggregate as well, or None.

  • name – Name of the ensemble score column.

Returns:

A float for one pair; otherwise a pandas.DataFrame: the pairs (a copy of the table, or columns source and target), the computed scores, and the column name.

Raises:

  • ValueError – If aggregation is not valid, if there are no scores to aggregate, if a method is not a score of this module, or if methods are given without net.

  • KeyError – If a column does not exist.

Example:

import graphoskop as gsk

train, validation = gsk.link_prediction_split(net, seed = 1)
methods = [gsk.common_neighbors_lp, "resource_allocation_lp", (gsk.local_random_walk_lp, {"steps": 3})]
validation = gsk.ensemble_link_prediction(train, validation, methods, name = "borda")
validation = gsk.ensemble_link_prediction(None, validation, aggregation = "kendall",
                                          columns = ["common_neighbors_lp", "resource_allocation_lp", "local_random_walk_lp"], name = "kemeny")
gsk.link_prediction_evaluation(validation, score = "kemeny")

Evaluation

A score is evaluated by how well it ranks the positives of the validation set above the negatives. In signed networks, the signs of the positives can also be predicted from the signs of the training network, by social balance or social status.

graphoskop.link_prediction_evaluation(validation, score='score', label='label', curves=False, points=101)

How well a score separates the positives from the negatives of a validation set.

  • auc: area under the ROC curve, the probability that a random positive has a higher score than a random negative (ties count one half); 0.5 for a random score, 1 for a perfect one.

  • average_precision: area under the precision-recall curve, the precision averaged over the positives, each at the threshold of its score (pairs with equal scores enter together, as in scikit-learn); the fraction of positives for a random score, 1 for a perfect one.

With curves = True, also the two curves, at points evenly spaced values of their x between 0 and 1, as tables ready to plot:

  • ROC curve: columns fpr (false positive rate, the fraction of the negatives scored at or above a threshold) and tpr (true positive rate, the same fraction of the positives), linearly interpolated between the thresholds (ties give a diagonal segment), with the highest tpr where the curve rises vertically;

  • precision-recall curve: columns recall (the true positive rate) and precision (the fraction of positives among the pairs at or above a threshold), at each recall the precision of the first threshold reaching it: a step function, whose area is average_precision (linear interpolation would overestimate precision between thresholds, see Davis and Goadrich, 2006).

Pairs with a NaN score are left out.

Parameters:

  • validation – pandas.DataFrame with a score column and a label column (1 for the positives, 0 for the negatives), e.g. from preferential_attachment_lp().

  • score – Name of the score column.

  • label – Name of the label column.

  • curves – Whether to also return the ROC and precision-recall curves.

  • points – Number of points of the curves, the first at 0 and the last at 1.

Returns:

Dictionary with keys "auc" and "average_precision" (floats) and, with curves, "roc_curve" and "precision_recall_curve" (pandas.DataFrame).

Raises:

ValueError – If there are no positives or no negatives, or fewer than 2 points.

Example:

import graphoskop as gsk

train, validation = gsk.link_prediction_split(net, seed = 1)
gsk.link_prediction_evaluation(gsk.preferential_attachment_lp(train, validation))
validation = gsk.adamic_adar_lp(train, validation, name = "aa")
result = gsk.link_prediction_evaluation(validation, score = "aa", curves = True)
result["auc"], result["average_precision"]
result["roc_curve"].plot(x = "fpr", y = "tpr")
result["precision_recall_curve"].plot(x = "recall", y = "precision")
graphoskop.link_prediction_sign_evaluation(net, validation, sign='sign', predictions=False)

How well social balance and social status predict the signs of the hidden edges of a signed network (Leskovec, Huttenlocher and Kleinberg, 2010): only the positives of the validation set (pairs that are connected in the full network) are evaluated, against their sign, from the two-step paths \(u - z - v\) through their common neighbors in the training network.

  • Social balance (“the friend of my enemy is my enemy”): a path predicts the product of the signs of its two edges, which would close a balanced triangle; directions are ignored. The vote of a pair is the sum of these products over all the paths, all the edges between \(u\) and \(z\) times all those between \(z\) and \(v\).

  • Social status (directed networks): a positive edge \(a \to b\) means that \(a\) regards \(b\) as higher in status, a negative one as lower, so it says \(\sigma_b - \sigma_a = \pm 1\). Each path gives \(\sigma_v - \sigma_u\), the sum of the differences along its two edges (followed in either direction), and the vote of a pair is the sum over the paths: the edge \(u \to v\) is predicted positive if \(v\) ranks higher.

A pair is predicted by the sign of its vote, and not predicted if the vote is 0 (no common neighbor, or a tie). Signs 0 or NaN in the training network count as absent edges.

Parameters:

  • net – The training network, a signed Network (see Signed networks), not multilayer.

  • validation – Validation set from link_prediction_split() of the signed network: columns source, target, label and the sign of the positives.

  • sign – Name of the sign edge attribute and of the sign column of validation.

  • predictions – Whether to also return the votes of every evaluated pair.

Returns:

Dictionary with "edges" (number of evaluated edges), "balance_accuracy" and "balance_coverage" (fraction of correct signs among the predicted edges, and fraction of the edges predicted), "status_accuracy" and "status_coverage" (NaN in undirected networks), and "majority_accuracy", the accuracy of predicting every edge with the most common sign of the training network, as a baseline. With predictions, also "predictions": the evaluated rows of validation with columns balance and status (the votes).

Raises:

  • ValueError – If the network is multilayer, or not signed.

  • KeyError – If validation has no sign column, or a node does not exist.

Example:

import graphoskop as gsk

net = gsk.load_network("signed_edges.tsv", directed = True)   # edge attribute "sign"
train, validation = gsk.link_prediction_split(net, seed = 1)
gsk.link_prediction_sign_evaluation(train, validation)

Performance

On two CPU threads, splitting a random network with 1,000,000 nodes and 5,000,000 edges (10% of the edges hidden, as many negatives) takes 2.8 s, most of it rebuilding the training network. Scoring the 1,000,000 pairs of the validation set takes 0.6 s by preferential attachment, 5-6 s by each of the common neighbor scores (2 s to sort the edges, 3 s to look up the 9,000,000 candidate common neighbors), 19 s by mutual information (most of it counting the triangles of every node), 4.6 s by local random walks of 2 steps, 11.5 s of 3 steps, 17 s of 4 steps, and 66 s by SimRank (100 walks of at most 10 steps per pair, random accesses to memory). Evaluating them takes 0.2 s, curves included. With 100,000 nodes and 500,000 edges, the split takes 0.2 s, the common neighbor scores 0.3 s, mutual information 1.3 s, local random walks 0.3-1 s, SimRank 2.2 s, the evaluation 0.01 s.

Vertex similarity solves a linear system per distinct node on one side of the pairs, so its time grows with the number of distinct nodes times the number of edges: on random networks with 5 edges per node and validation sets as above, 0.9 s with 2,000 nodes, 10 s with 5,000, 41 s with 10,000 (on the CPU; sparse products on a GPU are much faster).

Hierarchical random graphs and the block model reliability need thousands of sweeps of \(n\) moves of a sequential Markov chain, two chains in parallel on two threads (the first call also compiles them, a few seconds). A hierarchical random graph move takes about 0.3 microseconds, almost independently of the size of the network. With the default 5,000 sweeps of burn-in and 100 samples: under 0.1 s on the karate club (34 nodes), 0.1 s on 120 nodes and 541 edges, 0.9 s on 500 nodes and 4,158 edges, 1.8 s on 1,000 nodes and 9,323 edges, 3.9 s on 2,000 nodes and 18,489 edges; with 20,000 sweeps, which larger networks need (see hierarchical_random_graph_lp()), 3.5 s, 7 s and 16 s. A block model move costs the number of groups, so with the default 2,000 sweeps the reliability takes 0.1 s on the karate club, 0.5 s on 120 nodes, 5 s on 500 nodes and 13 s on 1,000.

For comparison, on the same networks and number of moves, the C++ implementation of hierarchical random graphs in igraph (Clauset’s original code, version 0.10.15, compiled with -O2, one thread) takes 1.2 microseconds per move on the karate club, 4.6 on 500 nodes, 6.5 on 1,000 and 12.5 on 2,000, and PyHRG (pure Python on networkx) 120 microseconds on the karate club and 520 on 500 nodes. igraph counts the edges between two subtrees by inserting the leaves of both into balanced search trees, a cost that grows with the subtrees; here every subtree is a range of positions in a leaf order, so the count only lists the neighbors of the smaller subtree. Both chains make the same moves and reach the same likelihoods after the same number of moves, with large differences between seeds in both.

How the scores compare (AUC, 10% of the edges hidden, as many negatives, default parameters, seed 1). The two groups have 60 nodes each, with edges only between groups (the best possible AUC is 0.78); the communities have 50 nodes each, with dense links within and few between (500 and 1,000 nodes).

Scores

Common neighbors

Two nodes with many neighbors in common are likely to become neighbors themselves (triadic closure). The scores of this family count the common neighbors of the two nodes, each with a weight, or as a fraction of all their neighbors, or with the links among them. Neighborhoods are sets (self loops and parallel edges ignored); in directed networks, the score of (u, v) counts the paths \(u \to z \to v\). They work best in assortative networks with many triangles, and give 0 to any pair at distance more than 2 (except mutual_information_index_lp(), which ranks those pairs by degree).

graphoskop.adamic_adar_lp(net, pairs, weight=None, name='score')

Adamic-Adar score of node pairs: the common neighbors, each counting \(1 / \log k_z\), so that common neighbors with few neighbors count more, \(\sum_{z \in \Gamma(u) \cap \Gamma(v)} 1 / \log k_z\) (Adamic and Adar, 2003). A common neighbor has at least the two neighbors u and v, so \(\log k_z > 0\).

Neighborhoods are as in common_neighbors_lp(); \(k_z\) is the number of neighbors of \(z\), in directed networks its in-neighbors plus its out-neighbors. With weight, each common neighbor counts \((w_{uz} + w_{zv}) / 2\) divided by \(\log(1 + s_z)\), with \(s_z\) its strength (Lü and Zhou, 2009, up to the factor 1/2); unlike the other scores, this does not reduce to the unweighted score when all weights are 1.

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • weight – Name of a numeric edge attribute (positive values), or None.

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is multilayer, or a pair does not have two nodes.

Example:

validation = gsk.adamic_adar_lp(train, validation)
graphoskop.car_index_lp(net, pairs, name='score')

CAR index of node pairs (Cannistraci, Alanis-Lobato and Ravasi, 2013): the number of common neighbors times the number of links among them, \(CN(u, v) \cdot LCL(u, v)\). Under the local community paradigm, two nodes are likely to connect if their common neighbors form a local community, i.e. are connected to one another, rather than being unrelated nodes that happen to be adjacent to both. Pairs whose common neighbors share no link score 0.

Neighborhoods are as in common_neighbors_lp(). In directed networks, the common neighbors of (u, v) are the nodes \(z\) of the paths \(u \to z \to v\), and the local community links are the arcs between two of them. Each pair costs the degrees of its common neighbors.

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node does not exist.

  • ValueError – If the network is multilayer, or a pair does not have two nodes.

Example:

validation = gsk.car_index_lp(train, validation)
graphoskop.common_neighbors_lp(net, pairs, weight=None, name='score')

Common neighbors score of node pairs: the number of neighbors that the two nodes share, \(|\Gamma(u) \cap \Gamma(v)|\), since two nodes with many friends in common are likely to become friends (triadic closure).

Neighborhoods are sets: self loops and parallel edges are ignored. In directed networks, \(\Gamma(u)\) holds the out-neighbors of u and \(\Gamma(v)\) the in-neighbors of v, so the score of (u, v) counts the paths \(u \to z \to v\). With weight, each common neighbor counts the mean weight of its two edges, \((w_{uz} + w_{zv}) / 2\) (the weights of parallel edges summed), as in Lü and Zhou (2009) up to the factor 1/2, so that the score is the unweighted one when all weights are 1.

Each pair costs the number of neighbors of its endpoint with fewer neighbors, and the pairs are processed in parallel, on the device of the network.

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • weight – Name of a numeric edge attribute, or None.

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is multilayer, or a pair does not have two nodes.

Example:

import graphoskop as gsk

train, validation = gsk.link_prediction_split(net, seed = 1)
validation = gsk.common_neighbors_lp(train, validation)
gsk.common_neighbors_lp(net, ("alice", "bob"), weight = "weight")
graphoskop.common_neighbors_jaccard_lp(net, pairs, weight=None, name='score')

Jaccard score of node pairs: the common neighbors as a fraction of all the neighbors of the two nodes, \(|\Gamma(u) \cap \Gamma(v)| / |\Gamma(u) \cup \Gamma(v)|\), 0 if both have no neighbors. Unlike common_neighbors_lp(), it does not favor pairs of hubs.

Neighborhoods are as in common_neighbors_lp(). With weight, the weighted Jaccard (Ruzicka) similarity of the two vectors of edge weights, \(\sum_z \min(w_{uz}, w_{zv}) / \sum_z \max(w_{uz}, w_{zv})\), the sums running over all nodes (weights of parallel edges summed, 0 for missing edges, positive values expected).

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • weight – Name of a numeric edge attribute (positive values), or None.

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is multilayer, or a pair does not have two nodes.

Example:

validation = gsk.common_neighbors_jaccard_lp(train, validation)
graphoskop.mutual_information_index_lp(net, pairs, name='score')

Mutual information score of node pairs (Tan, Xia and Zhu, 2014): how much knowing their common neighbors reduces the uncertainty about an edge between the two nodes, \(s_{uv} = \sum_{z \in \Gamma(u) \cap \Gamma(v)} I(L; z) - I(L_{uv})\).

  • \(I(L_{uv}) = -\log_2 p_{uv}\) is the self-information of an edge between \(u\) and \(v\) given only their degrees, with \(p_{uv} = 1 - \binom{M - k_v}{k_u} / \binom{M}{k_u}\) the probability that two nodes of these degrees are connected when \(M\) edges are placed at random: pairs of hubs are expected to be connected anyway, so their edge is less informative.

  • \(I(L; z)\) is what a common neighbor \(z\) tells about an edge between two of its neighbors: the mean, over the pairs \(m, n\) of its neighbors, of \(I(L_{mn}) - I(L_{mn} | z)\), where \(I(L_{mn} | z) = -\log_2 C_z\), with \(C_z\) the local clustering coefficient of \(z\).

A common neighbor whose neighbors are all unconnected (\(C_z = 0\)) makes the score \(-\infty\): the pair is ranked last. Pairs without common neighbors score \(-I(L_{uv})\), so they are ranked by degrees, like preferential_attachment_lp().

Neighborhoods are sets, as in common_neighbors_lp() (self loops and parallel edges ignored), and \(M\) is the number of connected pairs. Clustering coefficients are computed on the device of the network; the information of each node (a sum over the pairs of its neighbors, grouped by degree) is compiled with Numba, on the CPU.

Parameters:

  • net – An undirected Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node does not exist.

  • ValueError – If the network is directed or multilayer, or a pair does not have two nodes.

Example:

validation = gsk.mutual_information_index_lp(train, validation)
graphoskop.resource_allocation_lp(net, pairs, weight=None, name='score')

Resource allocation score of node pairs: the amount of a resource that u sends to v through their common neighbors, each of which splits what it receives equally among its neighbors, \(\sum_{z \in \Gamma(u) \cap \Gamma(v)} 1 / k_z\) (Zhou, Lü and Zhang, 2009). It punishes common neighbors with many neighbors more than adamic_adar_lp().

Neighborhoods and \(k_z\) are as in adamic_adar_lp(). With weight, each common neighbor counts \((w_{uz} + w_{zv}) / 2\) divided by its strength \(s_z\) (Lü and Zhou, 2009, up to the factor 1/2), the unweighted score when all weights are 1.

  • pairs – Pairs, as in preferential_attachment_lp().

  • weight – Name of a numeric edge attribute (positive values), or None.

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is multilayer, or a pair does not have two nodes.

Hierarchical random graphs

graphoskop.hierarchical_random_graph_lp(net, pairs, name='score', samples=100, burnin=5000, interval=1, chains=None, seed=None)

Hierarchical random graph score of node pairs (Clauset, Moore and Newman, 2008): the probability of an edge between the two nodes in hierarchical random graphs fitted to the network.

A hierarchical random graph is a dendrogram, a binary tree whose leaves are the nodes of the network, with a probability \(p_r\) at each internal node \(r\): two nodes are connected with the probability of their lowest common ancestor. Nodes in the same branch deep down the tree are therefore connected with a probability of their own, which can be high (communities) or low (e.g. the two types of a bipartite network), so that, unlike the common neighbor scores, the model also predicts edges in disassortative networks. Given a dendrogram, the likelihood is largest with \(p_r = E_r / (L_r R_r)\), the fraction of the pairs of leaves with \(r\) as lowest common ancestor (one in the left subtree, \(L_r\) leaves, and one in the right one, \(R_r\) leaves) that are connected (\(E_r\) edges), and its log is \(\sum_r E_r \log p_r + (L_r R_r - E_r) \log(1 - p_r)\).

Dendrograms are sampled in proportion to their likelihood by Markov chain Monte Carlo, from a random dendrogram: a move picks an internal node \(r\) and its parent, whose three subtrees below can be arranged in three ways, and proposes one of the other two, accepted with the Metropolis rule. Several independent chains, from different random dendrograms, run in parallel (one per CPU thread by default) and share the samples. Each chain first needs to reach dendrograms of high likelihood: burnin sweeps of \(n\) moves (\(n\) nodes) are discarded. Then each chain samples a dendrogram every interval sweeps, and the score of a pair is its mean edge probability over the samples dendrograms.

The likelihood climbs slowly, with long plateaus, and needs more sweeps on larger networks: it took about 2,000 sweeps to level off on the karate club (34 nodes), 3,000 on a network of 500 nodes with communities, 5,000 on one of 1,000 nodes, still drifting up slowly after that. With the default of 5,000 sweeps, the AUC was 0.86 on 1,000 nodes (0.87-0.88 with 20,000 sweeps) and 0.75-0.77 on 2,000 nodes (0.84 with 20,000 sweeps): give a larger burnin on larger networks. The posterior distribution of the dendrograms is rugged, so chains can keep sampling at different likelihood levels for a long time, and the convergence tests that compare chains, such as the potential scale reduction factor, rarely pass even when the predictions are stable: rather, compare the scores, or their AUC, between two seeds.

The model is undirected and unweighted: directions, weights, parallel edges and self loops are ignored. All the nodes of net are leaves of the dendrograms, isolated ones included. The leaves are kept in an order in which every subtree is a range of positions, so that the edges between two subtrees, needed by every move, are counted by listing the neighbors of the leaves of the smaller one and comparing their positions with the range of the other: a move costs the degrees of the leaves of a small subtree, and an accepted move moves the leaves of at most two subtrees. Fitting is still much slower than the other scores, since it needs thousands of sweeps (see the Performance section of Link prediction).

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • name – Name of the score column.

  • samples – Number of sampled dendrograms.

  • burnin – Number of sweeps of each chain before its first sample.

  • interval – Number of sweeps between samples.

  • chains – Number of chains, None for the number of Numba threads.

  • seed – Seed of the random numbers, or None for a random seed.

Returns:

Scores, as in preferential_attachment_lp(); 0 for a pair of a node with itself.

Raises:

  • KeyError – If a node does not exist.

  • ValueError – If the network is multilayer, a pair does not have two nodes, or samples, burnin or interval are not valid.

Example:

import graphoskop as gsk

train, validation = gsk.link_prediction_split(net, seed = 1)
validation = gsk.hierarchical_random_graph_lp(train, validation, samples = 200, seed = 1)
gsk.link_prediction_evaluation(validation)

Preferential attachment

graphoskop.preferential_attachment_lp(net, pairs, weight=None, name='score')

Preferential attachment score of node pairs: the product of the degrees of the two nodes, \(k_u k_v\), since in growth models such as the Barabási-Albert model the chance of a new edge grows with the degree of both its endpoints. In directed networks, the score of (u, v) is the out-degree of u times the in-degree of v, \(k_u^{out} k_v^{in}\). With weight, degrees are strengths (sums of the edge attribute, see degree()).

Degrees are computed in net: to test the score, give the training network and the validation set of link_prediction_split(). Degrees are computed on the device of the network.

  • net – A Network, not multilayer.

  • pairs – A pair (u, v) of node ids, an iterable of pairs, or a pandas.DataFrame with the endpoints in its first two columns (e.g. the validation set).

  • weight – Name of a numeric edge attribute for the weighted degree, or None.

  • name – Name of the score column.

Returns:

The score, a float, for one pair; otherwise a pandas.DataFrame: a copy of the table with the column name added, or columns source, target and name.

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is multilayer, or a pair does not have two nodes.

Example:

import graphoskop as gsk

Random walks

Two nodes are similar if random walkers move easily from one to the other, or, started at the two, soon meet. Unlike common neighbors, walks of a few steps also relate nodes farther apart.

graphoskop.local_random_walk_lp(net, pairs, steps=3, superposed=False, weight=None, name='score')

Local random walk score of node pairs (Liu and Lü, 2010): how likely a random walker started at one node is to be at the other after steps steps, from both sides, \(s_{uv}(t) = q_u \pi_{uv}(t) + q_v \pi_{vu}(t)\), where \(\pi_{uv}(t)\) is the probability that a walk of \(t\) steps from \(u\) ends at \(v\) and \(q_u = k_u / 2m\) the stationary probability of \(u\) (its share of the degrees). Few steps keep the walk local: \(t = 2\) gives a degree-weighted count of the common neighbors, larger \(t\) reaches pairs at distance up to \(t\). With superposed = True, the superposed random walk, \(\sum_{\tau = 1}^{t} s_{uv}(\tau)\), which favors nodes close to each other.

The walk moves to a uniformly random neighbor (with weight, to a neighbor with probability proportional to the weight of the edge); neighborhoods are sets, as in common_neighbors_lp() (self loops and parallel edges ignored, weights of parallel edges summed). In directed networks the walk follows the edges, and \(q_u\) is the share of the out-degrees. Only the pairs are scored: \(\pi_{uv}(t)\) is the product of the distribution after \(\lceil t / 2 \rceil\) steps from \(u\) and the probabilities of reaching \(v\) in the remaining steps, two sparse vectors with about \(k^{t / 2}\) entries each (\(k\) the average degree), computed with SciPy on the CPU.

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • steps – Number of steps \(t\), at least 1.

  • superposed – Whether to sum the scores of 1 to steps steps.

  • weight – Name of a numeric edge attribute (positive values), or None.

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is multilayer, a pair does not have two nodes, or steps is smaller than 1.

Example:

validation = gsk.local_random_walk_lp(train, validation, steps = 3)
validation = gsk.local_random_walk_lp(train, validation, steps = 3, superposed = True, name = "srw")
graphoskop.simrank_lp(net, pairs, decay=0.8, walks=100, length=10, seed=None, name='score')

SimRank similarity of node pairs (Jeh and Widom, 2002): two nodes are similar if they are pointed to by similar nodes,

\[s(u, v) = \frac{C}{|I(u)| |I(v)|} \sum_{a \in I(u)} \sum_{b \in I(v)} s(a, b), \qquad s(u, u) = 1,\]

with \(I(u)\) the in-neighbors of \(u\) (its neighbors in undirected networks) and \(C\) the decay; a node without in-neighbors is similar to no other node.

The exact scores need all the pairs of nodes at once (\(n^2\) values), so only the given pairs are estimated, from the random surfer-pairs model of Jeh and Widom: \(s(u, v) = E[C^t]\), where \(t\) is the first step at which two random walkers, started at \(u\) and \(v\) and moving at the same time to a random in-neighbor, meet. Each pair averages walks such pairs of walks, of at most length steps, in parallel over the pairs (compiled with Numba, on the CPU). The standard error is at most \(0.5 / \sqrt{walks}\), and stopping after length steps underestimates a score by less than \(C^{length + 1}\). Results depend on seed only, not on the number of threads.

Neighborhoods are sets, as in common_neighbors_lp() (self loops and parallel edges ignored).

Parameters:

  • net – A Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • decay – The decay \(C\), between 0 and 1.

  • walks – Number of pairs of walks per pair of nodes.

  • length – Largest number of steps of a walk.

  • seed – Seed of the random numbers, or None for a random seed.

  • name – Name of the score column.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node does not exist.

  • ValueError – If the network is multilayer, a pair does not have two nodes, or decay, walks or length are not valid.

Example:

validation = gsk.simrank_lp(train, validation, walks = 1000, seed = 1)

Stochastic block models

graphoskop.block_model_reliability_lp(net, pairs, name='score', samples=100, burnin=1000, interval=10, groups=None, chains=None, seed=None)

Stochastic block model reliability of node pairs (Guimerà and Sales-Pardo, 2009): the probability that the two nodes are connected, averaged over all the partitions of the nodes into groups, each weighted by how well a stochastic block model with those groups explains the network. In a block model, two nodes of groups \(\alpha\) and \(\beta\) are connected with a probability that depends only on the groups; with \(l_{\alpha\beta}\) links among the \(r_{\alpha\beta}\) pairs of nodes of the two groups, the reliability of a pair is

\[R_{uv} = \frac{1}{Z} \sum_P \frac{l_{\sigma_u \sigma_v} + 1}{r_{\sigma_u \sigma_v} + 2} \exp(-H(P)), \qquad H(P) = \sum_{\alpha \le \beta} \left[\ln(r_{\alpha\beta} + 1) + \ln \binom{r_{\alpha\beta}}{l_{\alpha\beta}}\right],\]

with \(\sigma_u\) the group of \(u\) in the partition \(P\). The partitions are sampled in proportion to \(\exp(-H(P))\) by Markov chain Monte Carlo: a move puts a random node in a random group (a new one, possibly), accepted with the Metropolis rule. Each chain starts from a random partition into \(\lceil \sqrt{n} \rceil\) groups, runs burnin sweeps of \(n\) moves (\(n\) nodes), then samples a partition every interval sweeps; the score of a pair is its mean reliability over the samples partitions. Chains are independent, one per CPU thread by default, and share the samples. Like hierarchical_random_graph_lp(), the model learns any pattern of connection between groups, assortative or not.

The model is undirected and unweighted: neighborhoods are sets, as in common_neighbors_lp() (self loops and parallel edges ignored). Partitions have at most groups groups (by default the number of nodes, at most 1,000): every chain keeps a groups by groups table of links between groups, and a move costs the degree of the node plus the number of non-empty groups. Compiled with Numba, on the CPU.

Parameters:

  • net – An undirected Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • name – Name of the score column.

  • samples – Number of sampled partitions.

  • burnin – Number of sweeps of each chain before its first sample.

  • interval – Number of sweeps between samples.

  • groups – Largest number of groups, None for the number of nodes, at most 1,000.

  • chains – Number of chains, None for the number of Numba threads.

  • seed – Seed of the random numbers, or None for a random seed.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node does not exist.

  • ValueError – If the network is directed or multilayer, a pair does not have two nodes, or samples, burnin, interval or groups are not valid.

Example:

validation = gsk.block_model_reliability_lp(train, validation, seed = 1)

Vertex similarity

graphoskop.vertex_similarity_lp(net, pairs, phi=0.9, weight=None, name='score', tol=1e-10, max_iter=10000)

Vertex similarity of node pairs (Leicht, Holme and Newman, 2006): two nodes are similar if their neighbors are similar, counting the paths of all lengths between them, each of length \(l\) weighted by \((\phi / \lambda_1)^l\), relative to the number expected in a random network with the same degrees,

\[S = 2 m \lambda_1 D^{-1} \left(I - \frac{\phi}{\lambda_1} A\right)^{-1} D^{-1},\]

with \(A\) the adjacency matrix, \(D\) the diagonal matrix of the degrees, \(\lambda_1\) the largest eigenvalue of \(A\), \(m\) the number of edges and \(0 < \phi < 1\): close to 1, long paths count almost as much as short ones. Unlike the local scores, it relates nodes at any distance (in the same component), like katz_centrality().

Neighborhoods are sets, as in common_neighbors_lp() (self loops and parallel edges ignored; with weight, \(A\) holds the weights, summed over parallel edges, \(D\) the strengths and \(2m\) their sum). Only the pairs are scored: the linear systems \((I - \phi A / \lambda_1) x = e_u\) are solved by conjugate gradients for the distinct nodes on one side of the pairs, a block at a time, on the device of the network; each costs a few tens of products with \(A\) (more as \(\phi\) approaches 1), so the time grows with the number of distinct nodes times the number of edges. Pairs with a node without neighbors score 0.

Parameters:

  • net – An undirected Network, not multilayer.

  • pairs – Pairs, as in preferential_attachment_lp().

  • phi – The parameter \(\phi\), between 0 and 1 (excluded).

  • weight – Name of a numeric edge attribute (positive values), or None.

  • name – Name of the score column.

  • tol – Relative residual at which conjugate gradients stop.

  • max_iter – Largest number of conjugate gradient iterations.

Returns:

Scores, as in preferential_attachment_lp().

Raises:

  • KeyError – If a node or the edge attribute does not exist.

  • ValueError – If the network is directed or multilayer, a pair does not have two nodes, phi is not between 0 and 1, or conjugate gradients do not converge.

Example:

validation = gsk.vertex_similarity_lp(train, validation, phi = 0.9)

Training and validation sets

graphoskop.link_prediction_split(net, fraction=0.1, negatives=1, seed=None, sign='sign')

Training network and validation set for link prediction.

A fraction of the connected node pairs of the network (self loops excluded) are drawn uniformly at random as positives, and all their edges are removed from the training network (parallel edges included and, in undirected networks, both directions). negatives times as many pairs of nodes that are not connected in net are drawn uniformly as negatives, without repetitions: pairs of distinct nodes anywhere in the network, also in different components, of different types in bipartite networks.

The training network keeps all the nodes, isolated ones included, with their attributes, and the attributes of the other edges; components are recomputed, since removing edges can split one.

In signed networks (with the numeric edge attribute sign, see Signed networks), the validation set also has a column named as sign, with the sign of each positive (+1 or -1; with parallel edges, the sign of the sum of their signs; NaN if it is 0 or for the negatives), for link_prediction_sign_evaluation().

Parameters:

  • net – A Network, not multilayer.

  • fraction – Fraction of the connected pairs hidden as positives, between 0 and 1.

  • negatives – Number of negatives per positive (rounded to the nearest integer in total).

  • seed – Seed of the random numbers, or None for a random seed.

  • sign – Name of the edge attribute holding the signs, if the network is signed.

Returns:

(train, validation): the training network, a new Network, and a pandas.DataFrame with columns source, target (node ids) and label (1 for the positives, which come first, 0 for the negatives), and sign in signed networks.

Raises:

ValueError – If the network is multilayer, if fraction is not between 0 and 1 or negatives is negative, or if there are not enough unconnected pairs.

Example:

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
train, validation = gsk.link_prediction_split(net, fraction = 0.2, negatives = 5, seed = 1)
edges, nodes = net.to_pandas_dataframes()
validation = validation.merge(nodes, left_on = "source", right_on = "node")   # source attributes
