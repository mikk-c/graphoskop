Progress bars

Progress bars of long computations, in the terminal (or as a widget in Jupyter, if ipywidgets is installed), with the time elapsed and the time left.

A bar appears as soon as a computation starts (or, with a delay set by set_progress(), only once it has run that long, so that shorter computations print nothing), and disappears when it ends. The bar follows the units of work the function does anyway (epochs, runs, swaps, removals), so nothing is estimated in advance and nothing is computed only for the bar: the time left is the time elapsed per unit, times the units left, and it is accurate when the units take about the same time (units of different sizes are weighted by their expected cost); it starts rough and improves as the computation advances. Updating a bar costs about 0.2 microseconds, against milliseconds or more for each unit of work. On a GPU, bars read no value from the device, so they never make it wait.

A function with a bar has a progress parameter: None (default) follows set_progress(), True or False turn its bar on or off. Inside a function with a bar (e.g. randomization_test() of edge_swap()), the inner functions show none: the outer bar covers them (and if it is off, they are off too).

Functions with a bar: cascade_failures() (average path length), diffpool(), edge_removal() and node_removal() (average path length, or recompute), edge_swap(), force_directed_layout(), gae(), gat(), gatv2(), gcn(), graphrnn() and simulate(), graphsage(), growing_manifold(), higher_order_dependency_network(), kuramoto_model(), memory_network(), metapath2vec(), nestedness() (null model), node2vec(), node_link_kuramoto_model(), randomization_test(), simplicial_kuramoto_model(), struc2vec(), umap_layout(), vgae().

import graphoskop as gsk

net = gsk.load_network("edges.tsv", "nodes.tsv")
out = gsk.gcn(net, "city", [32, 4], epochs = 2000)       # a bar while it runs
out = gsk.gcn(net, "city", [32, 4], progress = False)    # no bar for this call
gsk.set_progress(True, delay = 5)                         # bars only after 5 seconds
gsk.set_progress(False)                                   # no bars at all
graphoskop.set_progress(enabled=True, delay=0.0)

Turns the progress bars of all functions on or off, and sets how long a computation runs before its bar appears.

Parameters:

  • enabled – Whether to show progress bars.

  • delay – Seconds before a bar appears: 0 to show it at once, or e.g. 5 to show bars only for computations that last longer than that.

Example:

import graphoskop as gsk

gsk.set_progress(False)              # no bars (e.g. in batch jobs)
gsk.set_progress(True, delay = 5)    # bars only for computations longer than 5 seconds

In a terminal, a shown bar redraws at most 10 times a second (once every 30 seconds when the output is not a terminal, e.g. a log file), which cost nothing measurable either (a 7 s gcn() run redrawn 122 times took the same time as without a bar).

The time left is an estimate from the work done so far: it starts rough and becomes accurate as the computation advances (e.g. an adaptive attack of 9 s first estimated 6 s at 2 s, then 8 s at 3 s). Where units of work differ in size, they are weighted by their expected cost: in adaptive attacks each step counts the items still in the network; for path lengths, each point counts the sources of the searches times the items still in the network.
